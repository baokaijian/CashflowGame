# 现金流游戏 · 中国本土版

> 基于《富爸爸穷爸爸》现金流游戏的网页实现：**老鼠赛跑 → 财务自由圈** 双跑道、**101 + 202** 两套规则、**年龄 / 无限** 两种模式，并已完成中国本土化改造（货币、职业、收支科目、投资标的、市场与政策事件）。

纯静态前端，**没有任何构建步骤** —— 双击 `index.html` 就能玩。

## 玩法速览

### 三种游戏模式

| 模式 | 规则 | 结束条件 |
|---|---|---|
| **年龄模式**（默认） | 20 岁起步，**所有存活玩家各行动一次 = 一轮 = 长 1 岁** | 到 65 岁（共 45 轮）退休结算，**按净资产排名，最高者获胜** |
| **单人模式** | 同为年龄制，但**固定 1 位玩家**；61 岁起工资停发改领养老金，与他人相关的规则改由**机构**承接 | 到 65 岁退休结算，**按「达成时间 + 最终社会等级」评人生评级（S/A/B/C/D/F）** |
| **无限模式** | 不设年龄与轮数上限 | 一直玩到有人达成获胜条件 |

- 年龄 = `startAge + (round - 1)`；年龄模式下若有玩家提前买下梦想 / 企业达标，对局仍会提前结束。
- **单人模式例外**：达成梦想只记录年龄、**不结束对局**（要继续走完退休期），详见下文「单人模式」一节。
- 模式选择会随开局配置一起记入本地存档，下次打开开局页自动回填。

### 两套规则版本

| | 101 基础版 | 202 进阶版 |
|---|---|---|
| 出圈条件 | 被动收入 ＞ 总支出 **× 1.5** | 被动收入 ＞ **总支出 × 2.5** |
| 投资卡方向 | 小额理财 / 大额置业 | 杠杆交易 / 大额现金流 |
| 行情政策卡 | 16 张，波动温和 | 42 张，抽满 25 张重洗 |
| 交易方向 | 仅做多 | 做多 + 融券做空 + 期权 |
| 机会格 | 只抽投资卡 | 投资卡 + 行情卡同抽 |
| 房产 | 独立购买 | 可联合购买，租金随行情波动 |
| 财务自由圈企业 | 仅可购买 | 可开设特许经营 |
| 初始资产 | 仅职业卡 | 职业卡 + 随机投资组合卡 |

### 核心机制

| 机制 | 规则 |
|---|---|
| **起点 / 发薪日** | **到达与经过都触发**（路径含落点）：**结算一整年**，领取年度结余（年收入 − 年支出），并偿还贷款一年的本金（12 期）。一回合经过多个发薪日就结算多年，弹层会写明次数与合计 |
| **投资机会格** | 抽投资卡决定是否买入；买不起可把投资卡转让给其他玩家换现金（**单人模式无转让，只能买入或放弃**） |
| **市场行情格** | 抽行情政策卡，所有玩家的同类资产同时受到影响，可自行决定是否卖出 |
| **意外支出格** | 支付卡片金额，部分卡还会永久增加每月固定支出 |
| **添丁格** | 子女 +1（上限 3 个），每月养育支出增加 |
| **公益捐赠格** | 捐出总收入 10%，获得**银翅膀**（一次掷 3 粒骰子的机会）、**税前扣除节税**与精力回升 |
| **裁员失业格** | **领取**离职补偿（≈ 1 个月总支出），工资归零，进入**求职期**（见下节） |
| **精力** | 与现金并列的第二重资源：考察 / 买入 / 求职消耗，持有房产与企业持续消耗，见底触发健康危机 |
| **入不敷出** | 年度结余为负时记为缺口，走统一面板处理（动储蓄 / 变卖 / 贷款），**不会把现金扣成负数** |
| **发薪提示** | **经过**发薪日 / 分红日（未停留）时在顶栏下方弹出即时回执：`已发薪 ¥26,280 · 结算 20 岁这一年`。停在结算格由确认面板通知，纯入不敷出由缺口面板通知 —— 三者互斥，不会重复播报 |
| **消费升级** | 意外支出的**实付 = 卡片标价 × 消费档次系数**（由社会等级决定，L0 ×1.00 → L7 ×2.75）；一次性成本与每月维护成本**同时**放大。税费 / 罚款 / 医疗 / 人情只承接 25% |
| **休假** | 停在起点可花约一个月支出换回精力 —— 精力的主动恢复通道 |
| **现金约束** | **现金永不为负**：付不出必须三选一 —— 贷款补足 / 变卖资产（账面 80% 急售）/ 宣告破产 |
| **主动认输** | 随时可退出本局；**不清算资产**，名下资产负债完整保留并按净资产计入排名 |
| **被动破产** | 年度结余为负且已无资产可变现 → 银行按账面 50% 清算后出局 |
| **出圈（跳出老鼠赛跑）** | 被动收入 ＞ **门槛 = 总支出 × 安全边际**（101 ×1.5 / 202 ×2.5；见 [`docs/出圈门槛与投资回报标定.md`](docs/出圈门槛与投资回报标定.md)），进入财务自由圈并获得**出圈资金 = 月被动收入 × 100**（≈ 8.3 年被动收入）。席位卡与财务面板**实时显示出圈进度百分比**与「还差多少被动收入」 |
| **投资回报** | 投入口径年化：住宅 **5.2%** · 商业 **7.3%** · 实业 **9%—11%** · 固收 **5.8%**。首付比例：住宅 30% / 商业 45%（`YIELD.tier`）。**每 ¥1 月被动收入约需 ¥164—231 本金** |
| **生活基线** | **住房支出 = max(房贷月供, 住房基线)**，两者不叠加。还清房贷后成本不归零，所以出圈门槛不会随负债消失而崩塌（`LIFEBASE`） |
| **财务自由圈** | 掷 2 粒骰子；企业只能用现金买（不可贷款）；梦想格支付费用即获胜。**顺流层同样有账本**：分红要减生活支出（×1.35）与仍在还的贷款，**也一样会破产** |
| **信用额度** | 信用贷**不是想借多少有多少**：`min(年收入 × 1.2, DTI 剩余空间) × 信用系数`，另有资产抵押通道。失业 / 征信恢复期可被拒贷（`CREDIT`） |
| **期权** | 有效期 3 回合，逾期权利金损失 |
| **融券做空** | 不占用现金，但一旦出现该标的报价即**强制买回平仓** |
| **资产动态估值** | 抵押物按**当前市价**估值：`账面 × 行情周期（8 年 ±15%，各类资产相位错开）× 折旧（房产 0% / 企业 4% / 土地 −1%）`。租金变动卡会联动估值。**房价下行时你的可贷额度一起缩水**（`MARKET`） |
| **多头借贷识别** | 同时在多个**信用类**产品有余额、近期频繁申请信用贷、或额度使用率过高 → 降额；达红线**直接拒贷**。房贷 / 车贷 / 助学属正常负债，**不计入**（`CREDIT.multi`） |
| **退休与终局结算** | 61 岁退休时先把此前未结算的年份按**在职口径**结清再切换养老金；65 岁结束时补结最后一段 —— **一生结算的总年数 = 年龄跨度**，不会有年头凭空漏账 |
| **买断（202）** | 在财务自由圈可按对手资产账面价 × 1.5 买断，迫使其出局 |

### 出圈进度是怎么算的

**完成度 = 被动收入 ÷ 门槛**，其中**门槛 = 总支出 × 安全边际**（101 × 1.5；202 × 2.5）。
安全边际不是装饰：真实财务自由的通行标准（4% 法则隐含 25 倍年支出）本身留有缓冲，
支出会波动，零缓冲意味着任何一次意外都会击穿 —— 真实规划里没有人会在「被动收入 = 支出」那一刻辞职。
式子两边同时算数 —— 做高被动收入能推进进度，**提前还清贷款、压低总支出同样能推进进度**。

| 状态 | 显示 | 含义 |
|---|---|---|
| `progress` | `出圈 38%` | 仍在积累；财务面板给出「还差 ¥1,585 被动收入」 |
| `ready` | `出圈 100%`（绿） | 被动收入已超过门槛，点主按钮即可出圈 |
| `escaped` | `已出圈 100%`（绿） | 已在财务自由圈，出圈这件事视为已完成 |

> ⚠️ **门槛口径是「严格大于」**。因此 `pctText` 做了一次特殊处理：**只有真能出圈时才显示 100%，否则最多 99%** ——
> 否则会出现「100% 却还不能出圈」这种自相矛盾的读法。
> 这个口径只在 `Engine.escapeProgress` 里算一次：席位卡、财务面板、进度条宽度全部读同一个值，
> **界面不允许自己算比例**（否则迟早出现「条 38%、数字 39%」这类两套口径）。

### 人生模拟（精力 · 收支生命周期 · 逆流）

改造把《财富流沙盘》的三层人生结构与精力机制，结合中国现实重新标定后移植进来，
让决策从「只有钱一个维度」变成 **钱 × 精力 × 时间** 三维同时约束。
完整推导、现实依据与数值标定过程见 **[docs/人生模拟改造说明.md](docs/人生模拟改造说明.md)**。

| 机制 | 规则 |
|---|---|
| **精力值** | 上限随年龄衰减（35 岁 100 → 60 岁 70），每回合自然恢复（14 → 8）。考察投资 6—10 点、买入资产 2—20 点、求职 12 点；持有房产 / 企业 / 期权每回合扣 2—3 点维护精力。**跌破 30 主动收入打 8 折**，**归零触发健康危机**。不足时拒绝执行并说明还差多少 |
| **收入生命周期** | 工资 = 基础工资 × 年龄系数：`≤27:1.00 · 28-35:1.15 · 36-45:1.35 · 46-55:1.20 · 56-59:1.05 · 60+:1.00` |
| **支出生命周期** | 生活性支出按人生阶段浮动（0.85 → 1.15 → 1.05 → 0.95），**赡养父母按实发工资的 12%—13% 计**（40—59 岁） |
| **失业求职期** | 被裁领取补偿（≈ 1 个月总支出）→ 工资归零、支出照付 → 求职需 2 回合（40 岁 +1、50 岁再 +1），每回合投递耗 12 点精力；精力不足会拉长求职期 |
| **入不敷出** | 经过发薪日时**年度结余为负** → 记为缺口并弹出处理面板（动储蓄 / 变卖 / 贷款），补完后自动回到原落格继续结算 |
| **健康危机** | 精力归零 → 强制休养 2 回合，此后 4 回合每月新增医疗支出（≈ 半个月总支出），精力只回到上限一半，恢复效率减半 |
| **休假** | 停在起点可花约一个月支出换回 28 点精力 |

**三条被建模的真实规律**：

1. **时间是最公平的稀缺资源** —— 精力上限决定「能不能同时推进」，与「有没有钱」同等重要。
2. **中年才是最紧的时刻** —— 一生现金流的最低点统一落在 **56 岁**：收入已回落、赡养仍最高。
3. **失业的可怕之处是没有工资，不是罚款** —— 因此才需要应急金，也才有「越疲惫越难再就业」。

### 两条跑道如何交替（有人出圈之后）

**「圈」是每个玩家自己的状态**，不是全局状态 —— 这一点决定了有人出圈后游戏怎么继续：

| 状态 | 归属 | 说明 |
|---|---|---|
| `p.inFT` | 玩家 | 在内圈（老鼠赛跑）还是财务自由圈 |
| `p.pos` / `p.ftPos` | 玩家 | 两条跑道上的位置**分别记录、互不覆盖** |
| 骰子数 | 玩家 | 按**自己所在的圈**发放：内圈 1 粒、财务自由圈 2 粒 |
| 棋盘视图 | 界面 | 屏幕一次只显示一条跑道，属于**视图状态**，不属于玩家 |

由此得到三条规则：

1. **回合交替严格按座位顺序进行**（只有出局玩家会被跳过）。出圈不会让自己的回合变多或变少；
   **暂停回合**（裁员失业）也不会 —— 回合照样轮到你，只是本回合不能行动，交棒后轮到下一位。
2. **视图默认永远跟随当前行动玩家** —— 回合切换 / 掷骰 / 刷新恢复都会对齐，保证「轮到谁，板上就是谁的圈、谁的棋子位置」。
3. 想看别人时点棋盘中央的 **「👀 查看老鼠赛跑 / 查看财务自由圈」**：此时副标题会写明当前行动玩家在哪条跑道第几格；他一旦掷骰或回合切换，视图自动回到他的跑道（避免出现「我掷了骰子但棋子在屏幕上不动」的错觉）。两圈都有人时该按钮才出现。

> 实现要点：圈层判断一律用 `Engine.phaseOf(g, p)` 或 `p.inFT`。`g.phase` 只是「当前行动玩家所在圈」的**镜像**，为兼容旧存档保留，**不要用它做规则判断**（早期版本用它判断骰子数，导致一旦有人出圈，老鼠赛跑玩家也被发 2 粒骰子）。

### 贷款与提前还款

六类负债统一按**等额本息**建模，每笔贷款都有明确的**年供、月利率、剩余年数、剩余利息**，并且**全部支持提前还款**（旧版只能还信用贷）。

> **时间口径：一次发薪日 = 一年**（`TIME.monthsPerPayday = 12`）。合同按月计息，
> 但结算按年合并 —— 经过一次发薪日即偿还 **12 期**，
> 剩余期限 = 剩余期数 ÷ 12，以**年**显示。详见 [`docs/时间口径说明.md`](docs/时间口径说明.md)。

| 贷款类型 | 月息 | 年化 | 提前还款违约金 | 锁定期 |
|---|---|---|---|---|
| 房贷 | 0.41% | ≈4.9% | 免收 | 满 1 期 |
| 助学贷款 | 0.25% | ≈3.0% | 免收 | 无 |
| 车贷 | 0.55% | ≈6.6% | 还本额的 **2%** | 满 1 期 |
| 信用卡分期 | 0.60% | ≈7.2% | 还本额的 **3%** | 满 1 期 |
| 其他负债 | 0.40% | ≈4.8% | 免收 | 无 |
| 信用贷 | 1.00% | ≈12% | 免收 | 无（随借随还） |

**每期怎么还**：经过一次发薪日即偿还**一年**（12 期）—— 逐期计息：利息 = 剩余本金 × 月利率，月供的其余部分冲减本金。

> 旧版的负债余额是**冻结**的：每月照付月供，本金却永不减少。现在本金会真正下降，并在合同期内结清，年供随之从支出中消失（年结余立即改善）。
> 实测：房贷（约 140 期）在 **11 次发薪日 = 11 年** 时还清，正好落在「一轮 = 一年」的刻度上。

**提前还款怎么算**

- 应还现金 = **本次还本额 + 违约金**，违约金 = 还本额 × 该类贷款费率（上表）
- 部分提前还款**不得低于 1 期月供**；想一次还清请直接选「结清全部」
- 还款后二选一，与现实银行给的一致：
  - **年供不变 · 缩短期限** —— 省利息最多（默认）
  - **期限不变 · 降低年供** —— 减轻每年的还款压力
- 「贷款管家」面板实时给出前后对比：剩余本金 / 每年还款 / 剩余期限（年）/ 剩余利息 / **可节省利息**；
  界面预览与实际扣款**共用同一份计算**（`Engine.prepayPlan`），不会出现「算一套、扣另一套」

**剩余期限是怎么来的**：不写死，由 `(剩余本金, 月利率, 合同月供)` 反推**剩余期数**，再 ÷ 12 得到**年**。
因此职业卡上的月供与改造前的现金流**完全不变**，只是补上了原本缺失的「还剩几年、还剩多少利息」。

### 获胜条件（满足任一即结束）

1. 第一个在财务自由圈**买下自己的梦想**；
2. 第一个通过购买企业使**企业月现金流之和累计增加 ≥ ¥50,000**（资产规模的度量，与结算周期无关）；
3. 202 规则下**买断对手资产成为最后存活者**；
4. 年龄模式**到 65 岁按净资产排名第一**。

> **单人模式不使用这套判定**：没有可比的人，只能与时间比。
> 改为在 65 岁（或中途出局时）按「什么时候做到了什么」评出人生评级，见下文「单人模式」。

## 操作入口

**开局设置页**：游戏模式（年龄 / **单人** / 无限）→ 规则版本（101 / 202）→ 玩家人数（2—6，选单人模式时自动隐藏）→ 玩家名称 → 「显示对手财务明细」「快速动画」两个开关 → **「📖 游戏规则 · 如何跳出老鼠赛跑」**（默认展开，随规则版本同步切换门槛倍数与文案）→ 开始游戏。

**顶栏**：`☰` 菜单 · 轮次/年龄胶囊 · `🔄` 重置游戏 · 主题切换 · 规则速查

**抽屉菜单**：财务报表 · 玩家一览 · 规则速查 · 信用贷/还款 · 玩家间交易 · **📊 本局复盘报告** · 切换主题 · **🏳️ 主动认输** · 重新开始

**复盘报告底部**：**「⬇️ 导出分析」（Markdown，含全部参与者的维度数据与分析结论）** 与 **「⬇️ 导出 JSON」（结构化数据）**；战绩页同样有导出入口。

**右侧面板四个标签页**：财务（实时收入支出表 + 资产负债表 + **出圈进度与社会等级**）· 日志 · 规则 · 设置

**主操作区**：屏幕上任何时刻只有一个主操作 —— 未移动时是「掷骰子（N 粒）」，卡片结算中置灰为「处理卡片中…」，已移动且结算完则升为「结束回合 · 轮到 X」；正上方常驻回合状态条。

**键盘**：`空格` 掷骰 / 结束回合，`Esc` 关闭弹层。

## 架构说明

### 分层与依赖方向

```
数据层  data-*.js          ← 纯数据，只往 window 上挂常量
   ↓
逻辑层  engine.js          ← 纯函数引擎，不碰 DOM；只依赖数据层
        engine-actions.js  ← 操作层，读写引擎状态；只依赖引擎
   ↓
表现层  ui-core.js         ← 通用 UI 原子（弹层 / Toast / 表单 / 报表渲染）
        ui-pending.js      ← 卡片结算弹层
        ui-summary.js      ← 复盘报告
        ui-game.js         ← 主界面与回合流程（唯一持有 Game 状态的地方）
   ↓
引导层  main.js            ← 绑定启动，无业务逻辑
```

**引擎与 UI 完全解耦**：`engine.js` 内部没有任何 `document` / `window` 调用，可以单独在 Node 里 `eval` 起来跑对局（本项目的自动化验证就是这么做的）。

### 加载顺序（`index.html` 中不可调换）

```
data-careers → data-board → data-cards-101 → data-cards-202
  → engine → engine-actions
  → ui-core → ui-game → ui-pending → ui-summary
  → main
```

各文件都是 IIFE，只向 `window` 暴露一个命名空间：

| 命名空间 | 说明 |
|---|---|
| `Engine` | 引擎全部能力（财务推导、移动结算、破产、胜负、复盘采集…） |
| `Act` | 玩家操作函数 |
| `UI` | 通用 UI 原子 + `Setup` 开局配置对象 |
| `UiGame` | 主界面（含 `Game` 状态与 `startGame`） |
| `UiPending` | 卡片结算弹层（`showPending` / `face`） |
| `UiSummary` | 复盘报告（`openSummary` 等） |

### ⚠️ 界面与逻辑之间的硬契约

`engine` 通过**节点 ID 与 class 名**反向被 UI 绑定（例如 `.pcard__grid`、`.space--here`、`#paneFinance`、`#btnRollLabel`）。
**改类名或 ID 会静默失效**（不报错、只是不更新），动手前先 grep 一遍：

```bash
grep -rn "pcard__grid\|space--here\|paneFinance" js/ css/
```

## 数据模型

### 玩家对象（`newPlayer`）

```js
{
  id, seat, name, color, icon, job, salary, children, cash,
  liabs:  { home, school, car, credit, bank, other, extraPay },   // 负债（extraPay = 每月额外固定支出）
  assets: { stocks, realEstate, business, ftBusiness, savings, funds, lands, collectibles },
  pos, ftPos, inFT,                      // 内圈位置 / 财务自由圈位置 / 是否已出圈
  ftBase, ftGain,                        // 出圈时锁定的被动收入 / 财务自由圈累计企业现金流
  charityTurns, skipTurns,               // 公益加成剩余轮数 / 之后还有几个回合不能行动
  pausedThisTurn, pausedNotified,        // 本回合是否暂停（回合仍是你的，只是不能行动）
  dreamIdx, dreamOwned, options, shorts, franchise,
  turnsPlayed, out, outReason,
  loans,                                 // 贷款计划 { home:{base,due,periods}, ... }（见「贷款与提前还款」）
  stats, track, milestones,              // 复盘数据（见下）
  escaped, escapeRound, escapePassive, reportShown,
  // —— 人生模拟（精力 / 生命周期 / 逆流）——
  energy,                                // 精力（第二重资源，上限由年龄推导）
  baseSalary, salaryMult, salaryPhase, taxesCur,   // 收入生命周期（由年龄推导）
  lifeStage, lifeCoef, elderRatio, elderCare,      // 人生阶段（支出系数 + 赡养）
  joblessProgress, joblessNeed,          // 求职期进度 / 所需回合
  wings,                                 // 银翅膀（可换一次掷 3 粒）
  medicalExp, crisisTurns,               // 健康危机：每月医疗支出 / 剩余康复回合
  creditBanUntil,                        // 信用贷禁贷期（破产后的征信恢复期，到该轮为止不受理）
  loanDrawRounds,                        // 信用贷申请轮次（多头借贷识别「近期借了几次」的依据）
  retireSettled, retireRound             // 退休突变点是否已结清 / 发生在哪一轮（只触发一次）
}
```

> **`salary` / `taxesCur` / `elderCare` 是推导值，不要手写。** 它们全部由 `Engine.refreshLife(g, p)` 按当前年龄算出并写回玩家字段 ——
> 因此「长一岁 → 收入与支出结构随之变化」是一条可验证的因果链，而不是散落各处的手写常数。

**财务是实时推导的**：`Engine.finance(p)` 每次调用都从 `job` + `liabs` + `assets` 重新算出收入支出表与被动收入，不做缓存，因此任何操作后立即生效。

**资产对象额外带一个 `buyRound`**（由 `Engine.stampAsset(g, item)` 统一打标）：抵押物折旧依赖**持有年数**，
没有它就只能假设「从开局持有」。所有买入路径（含 `addStock` / `addCollectible` 两个辅助函数、
机构合伙、自由圈企业与特许经营）都在 `buyDeal` 末尾统一打标，组合卡的资产在开局记为第 1 轮。

### 贷款类型配置（`data-careers.js`）

```js
window.LOAN_TYPES = {
  home:  { nm:'房贷', rate:0.0041, prepayRate:0,    minPeriod:1, kind:'annuity' },
  car:   { nm:'车贷', rate:0.0055, prepayRate:0.02, minPeriod:1, kind:'annuity' },
  bank:  { nm:'信用贷', rate:0.01,  prepayRate:0,    minPeriod:0, kind:'revolving' },
  // school / credit / other 同理
};
window.LOAN_ORDER = ['home','school','car','credit','other','bank'];
```

- `rate` 月利率；`prepayRate` 提前还款违约金费率；`minPeriod` 允许提前还款前至少需还的期数
- `kind`：`annuity` 等额本息 / `revolving` 循环授信（信用贷，按余额计息、无固定期数）
- **`p.liabs.home/school/car/credit/other/bank` 仍然只存「剩余本金」这一个数字**，
  计划（原本金 / 月供 / 已还期数）另存在 `p.loans.<key>` —— 净资产、破产清算与存档格式因此零改动

### 卡片：三类字段结构（**不要混用**）

> 这是本项目最容易踩的坑：**投资卡与行情卡共用 `kind` 名，字段却完全不同**。渲染前必须先按牌堆分流，再按 `kind` 细分，否则会读到 `undefined` 渲染出 `$NaN`。

**① 投资卡**（`DECK_SMALL` / `DECK_BIG` / `DECK_CAPGAIN` / `DECK_CASHFLOW`）—— 可买标的

| `kind` | 关键字段 |
|---|---|
| `stock` | `symbol` `price` `min` `max` `range` |
| `realestate` | `nm` `tier`（`res`/`com`/`park`）`dp`（首付）`cost`（总价）`cf`（月现金流）`rent` `joint`（202 可联合购买）`capital`（纯资本利得型） |
| `business` | `nm` `tier`（`self`/`brand`/`equity`）`cost` `cf` `risky` |
| `savings` | `nm` `cost` `interest` |
| `land` | `nm` `cost`（等待行情报价） |
| `collectible` | `nm` `price` `min` `max`（`unit` 为可按单位买入） |
| `option` / `straddle` | `symbol` `dir`（call/put）`strike` `premium` |

**② 行情政策卡**（`DECK_MARKET_101` / `DECK_MARKET_202`）—— 报价 / 事件，**没有 `cost` 与 `cf`**

| `kind` | 关键字段 |
|---|---|
| `stock` | `symbol` `price` |
| `realestate` / `collectible` / `land` | `prop`（标的）`price` |
| `business` | `rate`（按购入价的倍率收购） |
| `savings` | `rate`（按本金比例兑现） |
| `rentDelta` | `pct`（全体出租房产租金浮动，202 专用） |
| `disaster` | `target`（受灾标的，资产归零） |
| `doodadLink` | 市场真空期（本轮无报价） |

**③ 意外支出卡**（`DECK_DOODAD_101` / `DECK_DOODAD_202`）—— 没有 `kind`，但有 `scale`

```js
{ id, nm, cost, extraPay?, scale:'life'|'basic', note }
// extraPay = 此后每月固定增加的支出
// scale    = 消费敏感度：'life' 随消费档次全额放大 / 'basic' 只承接 basicDamp 的比例
```

### 社会等级评估（`UiSummary.socialClassOf`）

用两条**真实的轴**定位玩家所处的层级，而不是按结局排名 —— 现实中决定一个人在哪一层的，
恰恰就是「对工资的依赖程度」与「扛得住多久的意外」：

| 轴 | 游戏内的度量 |
|---|---|
| 对工资的依赖程度 | 被动收入 ÷ 出圈门槛（覆盖度）—— 与报告里的「出圈进度」**同一口径** |
| 扛得住多久的意外 | 应急金 = 现金峰值 ÷ 月总支出（能撑几个月） |

| 等级 | 名称 | 判定条件 |
|---|---|---|
| L7 | 人生赢家 | 本局获胜 |
| L6 | 财务自由 | 已出圈，或被动收入已超过门槛 |
| L5 | 临门一脚 | 覆盖度 ≥ 80% |
| L4 | 稳健中产 | 覆盖度 ≥ 50% |
| L3 | 小有积累 | 覆盖度 ≥ 25% |
| L2 | 温饱有余 | 应急金 ≥ 3 个月支出 |
| L1 | 月光无余 | 未出局，但应急金不足 3 个月 |
| L0 | 入不敷出 | 已破产出局，或月现金流为负且无缓冲 |

> ⚠️ **低三层用「应急金」而不是「净资产」做门槛。** 这个游戏里每个人的初始净资产都被房贷拖成负数
> （现金 + 资产 − 剩余本金），拿它当「扛不扛得住」的信号，会把所有刚开局的人一律打成最底层；
> 而「能撑几个月」才是真实的抗风险刻度。

每一级都会给出三样东西：**判定依据**（4 项可自行核对）、**距离上一级的达成度**，
以及 3 条**针对该层级**的财商手段（回答的是「怎么往上走一层」，与「出圈诊断」那份结构性复盘分工不同）。

**对局中随时可见**：财务面板的「社会等级」区块随每次操作重算 —— 阶梯位置、等级名称、
距上一级的达成度都在那里，**不必等到对局结束，也不必打开复盘**。
它与复盘报告读的是**同一份评估**（`UiSummary.socialClassOf`，口径只有一处），
否则迟早会出现「面板说 L4、复盘说 L5」这种自相矛盾。

### 消费升级：地位的隐性成本（`LIFESTYLE`）

**规则一句话**：意外支出的 **实付金额 = 卡片标价 × 消费档次系数**，系数由社会等级决定。

**触发条件**：不是「抽到某张卡」才触发，而是**持续生效** —— 只要社会等级在某次操作后变化，
下一张意外支出卡就按新系数计价（等级判定见上一节：被动收入覆盖度 + 应急金）。

| 等级 | L0 | L1 | L2 | L3 | L4 | L5 | L6 | L7 |
|---|---|---|---|---|---|---|---|---|
| 消费档次系数 | ×1.00 | ×1.10 | ×1.25 | ×1.45 | ×1.75 | ×2.05 | ×2.40 | ×2.75 |

**为什么是这条曲线**：现实参照是「车价翻 5 倍，保养费大约 ×2—3」。消费档次不会因为你多赚一笔钱
就跳一档，但会持续爬升。每一档都配了一句可对照的现实解释，**在弹层里直接展示** ——
避免「凭空多收钱」的观感。

**合理整合进经济系统的三个关键决定**：

1. **按卡片敏感度分两类承接**（卡片的 `scale` 字段）
   - `scale:'life'` 消费升级型（修车 / 换车 / 房屋 / 出游 / 培训）→ **全额**承接系数
   - `scale:'basic'` 基础型（税费 / 罚款 / 医疗 / 人情）→ 只承接 `basicDamp`（25%）的比例

   > 否则「补缴个税」也会随豪车一起涨价，不合逻辑。22 张意外支出卡已全部标注。

2. **同时放大「一次性成本」与「每月维护成本」**（卡片的 `cost` 与 `extraPay`）

   > 这才是「持有成本」的真实形态：豪车不只是买得贵，而是保险、保养、配件持续更贵。
   > 例：L4 抽到「购置度假房产」，标价 ¥12,000 → **实付 ¥21,000**，且每月额外支出 ¥300 → **¥525**。

3. **只作用于意外支出，不作用于基础生活支出**

   > 基础支出反映「你要活下去」，意外支出反映「你维持这个档次要付出什么」。
   > 若把系数也乘到基础支出上，会和既有的「支出随人生阶段浮动」互相叠加、变成双重计费。

**可解释性是这条规则能被接受的关键**：

- 弹层把账摊开给玩家看：**档次 → 系数 → 卡片标价 → 档次加成 → 实付**，并附该档位的现实解释
- **金额在落格时锁定**并存进 `pending`，弹层与扣款读同一个数 —— 不允许界面自己再算一遍
- 卡面显示**实付金额**；也因此把 22 条硬编码了金额的备注改写成不含金额的描述，
  否则「备注写 ¥200、需支付写 ¥350」会让人以为系统算错了
- 财务面板常驻显示当前系数；复盘报告的判定依据里也列出「消费档次 ×1.75」
- 因档次多付的部分**单独记账**（`stats.doodadTierPaid`），可以回答「这条规则一共让我多花了多少」

**它的用意**：中高等级会额外拿到一条建议 —— 让资产表以**生息资产**（存款 / 基金 / 股票，不产生维护成本）为主，
把**消耗型资产**（豪车、豪宅、奢侈品）控制在必要范围内。
这才是这条规则真正要教的东西：**富人的风险不是买不起，而是养不起。**

### 单人模式：与自己的人生赛跑（`SOLO` · `SOLO_STAGES`）

**规则一句话**：同一条 20→65 岁的时间轴、同一套规则，把「和别人比谁先出圈」换成
「与自己的人生赛跑」；61 岁起工资停发改领养老金，没有其他玩家时由**机构**承接相关规则。

**与多人模式的差别只有三处**，其余（101/202、贷款、期权、做空、精力、失业求职、入不敷出、
消费升级、社会等级、慈善、银翅膀）**完全共用**：

| 差别 | 规则 | 现实依据 |
|---|---|---|
| **退休断崖** | 61 岁起工资 = 基础工资 × **45%**（养老金），且免征个税。**进入退休时先把此前未结算的年份按「在职」口径结清**，再切换 —— 否则会拿养老金的低口径去结算在职那几年，凭空造出缺口 | 城镇职工养老金替代率约 40%—50%；养老金免征个税见《个人所得税法》第四条 |
| **机构承接** | 202 大额房产可与**机构合伙人**联合（机构出 50% 首付、分 50% 现金流）。**机会转让整体取消** —— 单人下遇到机会只有「买入」或「放弃」 | 找投资人搭伙，让渡收益换取「买得起」；而「把机会卖出去换钱」在现实里没有对应场景，故不做替代 |
| **结算口径** | 不排名次，按「达成时间 + 最终社会等级」评 **S/A/B/C/D/F** | 一个人的人生没有可比对象，只能与时间比 |

**六个人生阶段**（边界与 `SALARY_CURVE` 对齐，退休期起点 = `SOLO.retireAge`）：

| # | 阶段 | 年龄 | 现实标签 | 核心矛盾 |
|---|---|---|---|---|
| 1 | 起步期 | 20—27 | 职场新人 | 攒下第一桶金 |
| 2 | 成长期 | 28—35 | 立业成家 | 把工资变成资产 |
| 3 | 巅峰期 | 36—45 | 收入黄金十年 | 趁高峰期完成原始积累 |
| 4 | 平台期 | 46—55 | 见顶回落 | 守住已有资产并完成出圈 |
| 5 | 冲刺期 | 56—60 | 最后一班车 | 退休前达成被动收入覆盖 |
| 6 | 退休期 | 61—65 | 没有工资，只有资产 | 靠资产活着 |

> **`SOLO_STAGES` 只写叙事、不含任何业务数值。** 收入倍数读 `SALARY_CURVE`、
> 支出与赡养读 `LIFE_STAGES`、精力读 `ENERGY`。阶段卡与财务报表**同时显示在界面上**，
> 若阶段表自带一份数值，迟早出现「阶段说 ×1.35、工资表说 ×1.20」这类自相矛盾 ——
> 回归里有一条断言专门守这件事。

**人生评级**：

| 结局 | 判据 | 评级 |

| 中途出局 | 破产 / 主动认输 | **F** |

**完成梦想不结束对局**（单人专属）：只记录达成年龄，对局继续到 65 岁 ——
目标是「完整走完一生」，同时更贴近财富流原意（进入顺流层后能否守住仍取决于后续决策）。

**结算无论怎么结束都会产出**：破产走的是 `checkLastStanding` 而不是「到 65 岁」，
所以结算被抽成独立的 `buildSoloResult(g)`，两条路径都调用它 ——
否则最常见的那条失败路径（中途破产）会没有任何总结可看。

完整推导见 [`docs/单人模式设计说明.md`](docs/单人模式设计说明.md)。

### 导出（Markdown / JSON）

复盘报告底部与战绩页各有导出入口。两种格式共用 `analyzeAll()` 的分析结果，
**保证两份文件说的是同一套数字**（两处各算一遍，迟早会对不上）：

- **Markdown** —— 按人分节，每位参与者一段：基本信息 / 关键指标 / 维度评分（6 维含加权总分）/
  社会等级评估（判定依据 + 提升手段）/ 出圈诊断与改进建议 / 下一局行动清单 / 关键决策时间线
- **JSON** —— 同源的**结构化数值**（指标为 `number`，可直接二次计算），含逐轮财富走势与节点时间线

文件名形如 `现金流复盘_101_年龄模式_第45轮_20260920-0936.md`；纯前端 Blob 下载，`file://` 下同样可用，不需要任何后端。

## 已知约束

这些都是当前实现里真实存在的边界，动手改之前建议先读一遍：

1. **数值是「对局平衡标定」，不等于现实**。金额量级沿用原版 1:1 映射为人民币，只调整了语义上明显脱离国内的项（信贷利率、支出科目、资产类型）。所以会看到「三甲医院医生月薪 ¥13,200」这类偏保守的数字；按真实收入/房价重算全表会连带影响出圈门槛与企业投资额，需要单独验证一轮平衡性。
2. **UI 与逻辑靠 ID / class 名硬契约绑定**，改类名不会报错，只会静默失效。
3. **202 的「破产后跳过回合 + 借贷限制」实际不生效** —— 因为当前规则是「破产即出局」，惩罚没有作用对象，仅保留在规则文案里。
4. **界面文案含 emoji**（📊 / 🏆 / 💀 等）。如果要按设计规范统一成 SVG 图标，需要做一轮图标替换。
5. **移动端是响应式降级**，不是独立设计：右栏下移、棋盘压缩、弹层转为底部 Sheet，未做专门的触控优化。
6. **没有测试框架，但有十一个可直跑的验证脚本**（`test/`）：职业现金流扫描、长局回归、
   消费升级计价自洽、单人模式、时间口径、发薪日触发审计、价格标定一致性、
   生活基线与信用额度、资产估值与多头借贷、出圈难度与投资回报、浏览器行为探针。
   它们零依赖、不需要 npm；浏览器探针仍需临时生成 `__probe.html` 并在用完后删除。
7. **`localStorage` 在隐私模式或配额超限时会静默降级**，此时刷新会回到开局页 —— 这是有意为之（不影响对局），但排查「进度丢了」时先确认这一点。
8. **棋盘坐标**依赖 CSS 的 7×7 网格与 `--g` / `--col` 计算，改棋盘尺寸时要同步检查 `RING_POS` 与 `game.css` 中 `.board` / `.board-center` 的公式。
9. **两条跑道共用一块屏幕**：`Game.boardView` + `Game.peeking` 是视图状态，一次只能显示一条跑道；
   两圈都有人的场景下，靠「跟当前玩家 + 可临时查看」来表达。若将来要做分屏 / 双方各自视图，改的是渲染层，不是引擎层。
10. **时间口径：一轮 = 一年，一次发薪日 = 一年**（`TIME.monthsPerPayday = 12`）。
   数据里的金额仍按「月」记录（职业卡的工资与月供、卡片上的月现金流），
   由引擎在发薪日合并成**年度结算**：领 12 个月的结余、还 12 期的本金，
   剩余期限 = 剩余期数 ÷ 12，以**年**呈现。
   **方案 A 已落地**：发薪日结算的是「自上次结算以来经过的年数」（`p.settledAge` 记账），
   不再是固定 1 年 —— 一生的结算覆盖率从 **44.4% 提到 93—100%**，两个时钟的刻度才真正一致。
   「一年只结一次账」：同一次移动经过多个发薪日只结第一个，摊还期数 = 结算年数 × 12。
   ⚠️ **不要退回「每个发薪日固定结 1 年」** —— 那会让一生的收入只覆盖 44% 的年头。
   ⚠️ **也不要试图「让发薪日推进年龄」** —— 一生只有约 19 次发薪，
   45 轮下来角色只活到 39 岁，65 岁退休判定立刻失效；而且会让「躲开发薪日」变成最优策略。
   完整推导、残差与价格标定见 [`docs/方案A与价格标定.md`](docs/方案A与价格标定.md)。
   **不要退回「一次发薪日 = 一个月」** —— 那个口径下 140 期的房贷一辈子还不完，
   而且玩家的被动收入永远够不着出圈门槛（实测），获胜条件形同虚设。
11. **「暂停回合」不删回合、只清行动权**：`Engine.markTurnPause(g)` 在每次交棒时结算 ——
   `skipTurns > 0` 的玩家会拿到 `pausedThisTurn = true`，回合**仍然属于他**（会正常轮到他、棋盘视图也会切到他），
   只是本回合不能掷骰 / 交易 / 借贷，界面给一张「⏸ 本回合暂停」提示卡点「交给下一位」。
   **不要退回「在 `nextPlayer` 里递归跳过该玩家」的写法** —— 两人局里那样会让对手连走三轮，
   看起来就像「已经出圈的那个人还在行动」，另一个人永远轮不到。
12. **`结束回合` 有 320ms 防连点**（`lastEndAt`）：它是「交棒」动作，双击会一次吃掉下一位的整个回合。
13. **人生模拟的参数是「对局平衡标定」，不等于现实**：`SALARY_CURVE` / `LIFE_STAGES` / `ENERGY` / `UNEMPLOYMENT`
    的取值一律取真实区间的**下沿**（例如收入峰值 1.35 倍，而真实职场可达 1.5—2 倍），
    目的是在不破坏原版平衡的前提下引入时间与精力压力。
    **改动这些参数后必须重跑**：全职业 × 全年龄现金流扫描、长局回归、单人模式 ——
    首版就曾因「赡养用固定金额」导致全员在中年必然破产（低收入职业被扣掉半个收入）。
14. **单人模式的退休断崖是「单人专属」**：`SOLO.retireAge = 61` 起工资降为养老金的逻辑
    在引擎里由 `isSolo(g)` 把关，**多人年龄模式完全不受影响**（65 岁同步结算，这道断崖不产生相对压力）。
    回归里有一条断言专门守这件事：多人模式在 65 岁时 `p.retired === false` 且税负未被清零。
15. **`SOLO_STAGES` 不得写入任何业务数值**。它只是叙事层，收入读 `SALARY_CURVE`、
    支出读 `LIFE_STAGES`、精力读 `ENERGY`。阶段卡与财务报表同时显示在界面上，
    阶段表若自带数值就会出现两套口径。`test/solo-mode.js` 有一条断言扫描本表的字段类型。
16. **发薪日的结算明细必须由 `movePlayer` 落进 `landed.settled` 再交给弹层读**（`{ count, amount, deficit, years[] }`）。
   弹层**不允许自己再算一遍金额** —— 旧版就是在 `resolveSpace` 里写了 `finance(p).cashflow`（月度值），
   而引擎实发的是 `annual(...)`（年度值），弹出 ¥674、到账 ¥8,088。
   摘要必须挂在 `landed` 上而不是球员对象或全局：入不敷出处理完后界面会带着
   `Object.assign({}, landed, {deficit:0})` 回到 `resolveSpace`，挂错地方就会丢。
   **一回合可以结算多年**（1 粒骰最多 2 个、3 粒骰最多 3 个发薪日，外圈分红日最多 8 个），
   所以弹层要显示的是【合计】而不是单年的值 —— 而且各年金额可能不同
   （前一次摊还若还清某笔贷款，月供会立刻消失）。
17. **骰子上限受环长约束**：3 粒骰上限 18 步 < 环长 24，所以一回合不可能绕满整圈。
   若将来把上限提到 24 步（4 粒骰），同一发薪日会被结算两次 ——
   `pathBetween`（guard 60）与 `movePlayer`（无去重保护）都要先改。
18. **住房基线是「地板」不是「叠加项」**：`住房支出 = max(房贷月供, 住房基线)`。
    ⚠️ 不要改成「房贷月供 + 基线」（开局会对所有职业双算，直接改变基础平衡），
    也不要只把基线放进门槛而不放进支出（那样现金流会因还清贷款而暴涨，同样不真实）。
    回归里有一条断言守这件事：**12 个职业在【有房贷】时住房缺口恒为 0**。
19. **圈层相关的数值只能有一个真源：`Engine.settleCashflow(p)`**。
    老鼠赛跑看「工资 + 被动 − 支出」，财务自由圈看「分红 − 自由圈支出 − 贷款」——
    界面上的每一处「年结余」都必须读它，**不允许各处自己判断圈层**。
    曾经出过 bug：分红日按自由圈账本入账，顶栏却仍显示工资口径的年结余，
    同一屏上出现 ¥59,928 与 ¥97,824 两个数。回归里有跨模块一致性断言。
20. **信用贷的额度、拒绝原因、按钮可用状态三者必须同源**（都来自 `Engine.creditProfile`），
    `takeLoan` 也要用同一份判定 —— 否则会出现「面板说不能借、点了却借到了」。
    另：**被拒时不能改动账目**（回归里有断言：被拒后现金与负债分文未动）。
21. **资产估值有两个口径，不要合并**：`账面成本`（`cost` / `dp`，用于**净资产与卖出计价**）与
    `当前估值`（`appraiseAsset`，**只用于抵押授信**）。这不是「两套口径」，而是现实中真实存在的差异
    （会计账面价值 vs 评估价）。界面在贷款管家与财务面板上把两者**并列展示**并写出差额百分比 ——
    改动其中任一方时，记得这是**有意的差异**，不要顺手「统一」掉。
22. **`MARKET` 的 `cycle.phase` / `decay` / `haircut` 三张表，键名必须与 `ASSET_KINDS` 完全一致**
    （复数形式：`lands` / `collectibles`，不是 `land` / `collectible`）。
    写成单数 key **不会报错，只会被静默忽略** —— 首版就是因此让土地与房产同相、同步涨跌。
    `test/market-valuation.js` 有一条断言扫描这三张表，要求**无越界键、无遗漏项**。
23. **资产必须带 `buyRound`**（由 `Engine.stampAsset(g, item)` 打标，见「数据模型」）。
    新增任何买入路径时，接到 `buyDeal` 末尾的统一打标里，或显式调用 `stampAsset` ——
    漏掉的资产会被当作「从开局持有」，**折旧年限直接少算**。
24. **信用贷的申请轮次要记进 `p.loanDrawRounds`**（`takeLoan` 内，只保留最近 `drawWindow × 3` 条）。
    多头借贷识别完全依赖它，漏记等于风控失效。
    ⚠️ 行情的价格周期是**确定性函数**（`Math.sin`，不含随机数）—— 不要为了「更真实」改成随机，
    那会让存档、复盘与回归全部失去可复现性。
25. **`cfg.seed` 必须覆盖【全部】随机入口**：职业洗牌、组合卡洗牌、各副牌堆、
    牌堆重洗（`deck.rnd`）与掷骰（`g.rng`）。**新增任何随机点都要接上它**。
    只覆盖一半比完全不支持更危险 —— 会让人以为「已经可复现」，
    于是回归里那些数值断言会在某个不可控的时刻突然变红，而排查方向被完全误导
    （本项目就曾因此追着资产估值查了半天，真凶其实是洗牌）。
    不传 seed 时 `rng = null`，各处退回 `Math.random()`。
26. **发薪提示不参与任何结算**：`paydayNoticeOf` 只读 `landed.settled` 并返回数据，
    `UiCore.paydayNotice` 只渲染。**不要把它做成结算的副作用**（例如塞进 `movePlayer` 里改字段）——
    那会让引擎依赖界面，破坏「引擎零 DOM 依赖、可在 Node 里直接跑长局回归」这条约定。
    判定（该不该提示）在引擎、文案与样式在界面，这个分工是刻意的。
27. **投资回报的四个字段是一个联动的整体**（`dp` → 贷款 → 月供 → `cf`），
    **不要手改其中任何一个**：它们由 `tools/rebalance-returns.js` 从 `cost` 与 `window.YIELD` 反算。
    手改会破坏约束，而**这类错误不会报错** —— 只会让玩家算出对不上的账。
    改完必须重跑 `test/escape-difficulty.js`（它逐卡对账，并检查备注里的金额与字段同值）。
    ⚠️ 备注里的金额也必须一起改 —— 备注由工具重新生成，手改字段不改备注就会出现
    「卡面写 ¥2,688、备注写 ¥3,600」（价格标定那一轮已经踩过）。
28. **出圈门槛倍数只能从 `Engine.escapeMargin(g)` 读**。它出现在 6 处（开局页规则模块、
    规则版本说明、财务面板、规则页 ×2、复盘进度、开局日志），**任何一处写死都会造成同屏两套口径**。
    本项目就漏改过一处（规则版本下方那行 `跳出条件：被动收入 > 总支出`），
    正则扫描没抓到（它用的是普通 `>` 而非 `&gt;`），最后是**截图时肉眼发现的**。
29. **企业达标线只能从 `Engine.empireTarget()` 读**。原先它在 20 处硬编码
    （3 处胜利判定 + 2 处里程碑文案 + 15 处界面文案），改收益口径时必然漏改。
    它的数值与投资回报**同源**：收益口径下调时达标线必须同比例下调，
    否则「把全部 7 家企业都买下」也达不到（全部买下只有约 ¥54,735/月）。
30. **未建模的真实缺口**（已知但未做，详见 `docs/人生模拟改造说明.md` 第六节、
    `docs/单人模式设计说明.md` 第八节与 `docs/资产估值与多头借贷.md` 第六节）：
    子女成年后养育支出不下降、精力维护成本对资产数量是线性的（现实中 5 套房产的管理成本不是 1 套的 5 倍）、
    养老金不与缴费年限挂钩、房产不支持换手（不能卖出再买回同一套）、
    退休后医疗支出不随年龄抬升、单人模式的机构合伙人是无个性的固定对手、
    **抵押物估值与行情卡报价不是同一个数**（前者按周期估算，后者是成交价；对股票尤其明显）、
    折旧按类别一刀切（同类资产完全同步）、企业折旧没有下限、
    多头借贷不含「跨机构查询次数 / 为他人担保」等真实征信维度、
    **房产的资本利得未随首付比例同步标定**（行情卡收购价仍是旧口径，与新的首付比例需一起复核）、
    门槛仍随负债结清而下降（安全边际是统一倍数，不改变门槛形状；
    住房基线只挡住了住房那部分，车贷 / 信用卡结清后的持续成本未建模）
    —— 详见 [`docs/出圈门槛与投资回报标定.md`](docs/出圈门槛与投资回报标定.md) 第六节。
