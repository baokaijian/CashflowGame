# 现金流游戏 · 中国本土版

> 基于《富爸爸穷爸爸》现金流游戏的网页实现：**老鼠赛跑 → 财务自由圈** 双跑道、**101 + 202** 两套规则、**年龄 / 无限** 两种模式，并已完成中国本土化改造（货币、职业、收支科目、投资标的、市场与政策事件）。

纯静态前端，**没有任何构建步骤** —— 双击 `index.html` 就能玩。

open index.html            # macOS
# Windows / Linux 双击 index.html 亦可

## 玩法速览

### 两种游戏模式

| 模式 | 规则 | 结束条件 |
|---|---|---|
| **年龄模式**（默认） | 20 岁起步，**所有存活玩家各行动一次 = 一轮 = 长 1 岁** | 到 65 岁（共 45 轮）退休结算，**按净资产排名，最高者获胜** |
| **无限模式** | 不设年龄与轮数上限 | 一直玩到有人达成获胜条件 |

- 年龄 = `startAge + (round - 1)`；年龄模式下若有玩家提前买下梦想 / 企业达标，对局仍会提前结束。
- 模式选择会随开局配置一起记入本地存档，下次打开开局页自动回填。

### 两套规则版本

| | 101 基础版 | 202 进阶版 |
|---|---|---|
| 出圈条件 | 被动收入 ＞ 总支出 | 被动收入 ＞ **总支出 × 2** |
| 投资卡方向 | 小额理财 / 大额置业 | 杠杆交易 / 大额现金流 |
| 行情政策卡 | 16 张，波动温和 | 42 张，抽满 25 张重洗 |
| 交易方向 | 仅做多 | 做多 + 融券做空 + 期权 |
| 机会格 | 只抽投资卡 | 投资卡 + 行情卡同抽 |
| 房产 | 独立购买 | 可联合购买，租金随行情波动 |
| 财务自由圈企业 | 仅可购买 | 可开设特许经营 |
| 初始资产 | 仅职业卡 | 职业卡 + 随机投资组合卡 |

### 核心机制

| 机制 | 规则 |
|---|---|
| **起点 / 发薪日** | 经过或停在发薪日，领取一次月现金流（收入 − 支出） |
| **投资机会格** | 抽投资卡决定是否买入；买不起可把投资卡转让给其他玩家换现金 |
| **市场行情格** | 抽行情政策卡，所有玩家的同类资产同时受到影响，可自行决定是否卖出 |
| **意外支出格** | 支付卡片金额，部分卡还会永久增加每月固定支出 |
| **添丁格** | 子女 +1（上限 3 个），每月养育支出增加 |
| **公益捐赠格** | 捐出总收入 10%，获得**银翅膀**（一次掷 3 粒骰子的机会）、**税前扣除节税**与精力回升 |
| **裁员失业格** | **领取**离职补偿（≈ 1 个月总支出），工资归零，进入**求职期**（见下节） |
| **精力** | 与现金并列的第二重资源：考察 / 买入 / 求职消耗，持有房产与企业持续消耗，见底触发健康危机 |
| **入不敷出** | 月现金流为负时记为缺口，走统一面板处理（动储蓄 / 变卖 / 贷款），**不会把现金扣成负数** |
| **消费升级** | 意外支出的**实付 = 卡片标价 × 消费档次系数**（由社会等级决定，L0 ×1.00 → L7 ×2.75）；一次性成本与每月维护成本**同时**放大。税费 / 罚款 / 医疗 / 人情只承接 25% |
| **休假** | 停在起点可花约一个月支出换回精力 —— 精力的主动恢复通道 |
| **现金约束** | **现金永不为负**：付不出必须三选一 —— 贷款补足 / 变卖资产（账面 80% 急售）/ 宣告破产 |
| **主动认输** | 随时可退出本局；**不清算资产**，名下资产负债完整保留并按净资产计入排名 |
| **被动破产** | 月现金流为负且已无资产可变现 → 银行按账面 50% 清算后出局 |
| **出圈（跳出老鼠赛跑）** | 被动收入 ＞ 门槛，进入财务自由圈并获得**出圈资金 = 被动收入 × 100**。席位卡与财务面板**实时显示出圈进度百分比**与「还差多少被动收入」 |
| **财务自由圈** | 掷 2 粒骰子；企业只能用现金买（不可贷款）；梦想格支付费用即获胜 |
| **期权** | 有效期 3 回合，逾期权利金损失 |
| **融券做空** | 不占用现金，但一旦出现该标的报价即**强制买回平仓** |
| **买断（202）** | 在财务自由圈可按对手资产账面价 × 1.5 买断，迫使其出局 |

### 出圈进度是怎么算的

**完成度 = 被动收入 ÷ 门槛**（101 门槛 = 总支出；202 = 总支出 × 2）。
式子两边同时算数 —— 做高被动收入能推进进度，**提前还清贷款、压低总支出同样能推进进度**。

| 状态 | 显示 | 含义 |
|---|---|---|
| `progress` | `出圈 38%` | 仍在积累；财务面板给出「还差 ¥1,585 被动收入」 |
| `ready` | `出圈 100%`（绿） | 被动收入已超过门槛，点主按钮即可出圈 |
| `escaped` | `已出圈 100%`（绿） | 已在财务自由圈，出圈这件事视为已完成 |

> ⚠️ **门槛口径是「严格大于」**。因此 `pctText` 做了一次特殊处理：**只有真能出圈时才显示 100%，否则最多 99%** ——
> 否则会出现「100% 却还不能出圈」这种自相矛盾的读法。
> 这个口径只在 `Engine.escapeProgress` 里算一次：席位卡、财务面板、进度条宽度全部读同一个值，
> **界面不允许自己算比例**（否则迟早出现「条 38%、数字 39%」这类两套口径）。

### 人生模拟（精力 · 收支生命周期 · 逆流）

改造把《财富流沙盘》的三层人生结构与精力机制，结合中国现实重新标定后移植进来，
让决策从「只有钱一个维度」变成 **钱 × 精力 × 时间** 三维同时约束。
完整推导、现实依据与数值标定过程见 **[docs/人生模拟改造说明.md](docs/人生模拟改造说明.md)**。

| 机制 | 规则 |
|---|---|
| **精力值** | 上限随年龄衰减（35 岁 100 → 60 岁 70），每回合自然恢复（14 → 8）。考察投资 6—10 点、买入资产 2—20 点、求职 12 点；持有房产 / 企业 / 期权每回合扣 2—3 点维护精力。**跌破 30 主动收入打 8 折**，**归零触发健康危机**。不足时拒绝执行并说明还差多少 |
| **收入生命周期** | 工资 = 基础工资 × 年龄系数：`≤27:1.00 · 28-35:1.15 · 36-45:1.35 · 46-55:1.20 · 56-59:1.05 · 60+:1.00` |
| **支出生命周期** | 生活性支出按人生阶段浮动（0.85 → 1.15 → 1.05 → 0.95），**赡养父母按实发工资的 12%—13% 计**（40—59 岁） |
| **失业求职期** | 被裁领取补偿（≈ 1 个月总支出）→ 工资归零、支出照付 → 求职需 2 回合（40 岁 +1、50 岁再 +1），每回合投递耗 12 点精力；精力不足会拉长求职期 |
| **入不敷出** | 经过发薪日时月现金流为负 → 记为缺口并弹出处理面板（动储蓄 / 变卖 / 贷款），补完后自动回到原落格继续结算 |
| **健康危机** | 精力归零 → 强制休养 2 回合，此后 4 回合每月新增医疗支出（≈ 半个月总支出），精力只回到上限一半，恢复效率减半 |
| **休假** | 停在起点可花约一个月支出换回 28 点精力 |

**三条被建模的真实规律**：

1. **时间是最公平的稀缺资源** —— 精力上限决定「能不能同时推进」，与「有没有钱」同等重要。
2. **中年才是最紧的时刻** —— 一生现金流的最低点统一落在 **56 岁**：收入已回落、赡养仍最高。
3. **失业的可怕之处是没有工资，不是罚款** —— 因此才需要应急金，也才有「越疲惫越难再就业」。

### 两条跑道如何交替（有人出圈之后）

**「圈」是每个玩家自己的状态**，不是全局状态 —— 这一点决定了有人出圈后游戏怎么继续：

| 状态 | 归属 | 说明 |
|---|---|---|
| `p.inFT` | 玩家 | 在内圈（老鼠赛跑）还是财务自由圈 |
| `p.pos` / `p.ftPos` | 玩家 | 两条跑道上的位置**分别记录、互不覆盖** |
| 骰子数 | 玩家 | 按**自己所在的圈**发放：内圈 1 粒、财务自由圈 2 粒 |
| 棋盘视图 | 界面 | 屏幕一次只显示一条跑道，属于**视图状态**，不属于玩家 |

由此得到三条规则：

1. **回合交替严格按座位顺序进行**（只有出局玩家会被跳过）。出圈不会让自己的回合变多或变少；
   **暂停回合**（裁员失业）也不会 —— 回合照样轮到你，只是本回合不能行动，交棒后轮到下一位。
2. **视图默认永远跟随当前行动玩家** —— 回合切换 / 掷骰 / 刷新恢复都会对齐，保证「轮到谁，板上就是谁的圈、谁的棋子位置」。
3. 想看别人时点棋盘中央的 **「👀 查看老鼠赛跑 / 查看财务自由圈」**：此时副标题会写明当前行动玩家在哪条跑道第几格；他一旦掷骰或回合切换，视图自动回到他的跑道（避免出现「我掷了骰子但棋子在屏幕上不动」的错觉）。两圈都有人时该按钮才出现。

> 实现要点：圈层判断一律用 `Engine.phaseOf(g, p)` 或 `p.inFT`。`g.phase` 只是「当前行动玩家所在圈」的**镜像**，为兼容旧存档保留，**不要用它做规则判断**（早期版本用它判断骰子数，导致一旦有人出圈，老鼠赛跑玩家也被发 2 粒骰子）。

### 贷款与提前还款

六类负债统一按**等额本息**建模，每笔贷款都有明确的**月供、月利率、剩余期数、剩余利息**，并且**全部支持提前还款**（旧版只能还信用贷）。

| 贷款类型 | 月息 | 年化 | 提前还款违约金 | 锁定期 |
|---|---|---|---|---|
| 房贷 | 0.41% | ≈4.9% | 免收 | 满 1 期 |
| 助学贷款 | 0.25% | ≈3.0% | 免收 | 无 |
| 车贷 | 0.55% | ≈6.6% | 还本额的 **2%** | 满 1 期 |
| 信用卡分期 | 0.60% | ≈7.2% | 还本额的 **3%** | 满 1 期 |
| 其他负债 | 0.40% | ≈4.8% | 免收 | 无 |
| 信用贷 | 1.00% | ≈12% | 免收 | 无（随借随还） |

**每期怎么还**：经过一次发薪日即偿还一期 —— 利息 = 剩余本金 × 月利率，月供的其余部分冲减本金。

> 旧版的负债余额是**冻结**的：每月照付月供，本金却永不减少。现在本金会真正下降，并在最后一期结清，月供随之从总支出中消失（月现金流立即改善）。

**提前还款怎么算**

- 应还现金 = **本次还本额 + 违约金**，违约金 = 还本额 × 该类贷款费率（上表）
- 部分提前还款**不得低于 1 期月供**；想一次还清请直接选「结清全部」
- 还款后二选一，与现实银行给的一致：
  - **月供不变 · 缩短期限** —— 省利息最多（默认）
  - **期限不变 · 减少月供** —— 降低月度压力
- 「贷款管家」面板实时给出前后对比：剩余本金 / 每月还款 / 剩余期数 / 剩余利息 / **可节省利息**；
  界面预览与实际扣款**共用同一份计算**（`Engine.prepayPlan`），不会出现「算一套、扣另一套」

**剩余期数是怎么来的**：不写死，由 `(剩余本金, 月利率, 合同月供)` 反推。因此职业卡上的月供与改造前的现金流**完全不变**，只是补上了原本缺失的「还剩几期、还剩多少利息」。

### 获胜条件（满足任一即结束）

1. 第一个在财务自由圈**买下自己的梦想**；
2. 第一个通过购买企业使**月现金流累计增加 ≥ ¥50,000**；
3. 202 规则下**买断对手资产成为最后存活者**；
4. 年龄模式**到 65 岁按净资产排名第一**。

## 操作入口

**开局设置页**：游戏模式（年龄 / 无限）→ 规则版本（101 / 202）→ 玩家人数（2—6）→ 玩家名称 → 「显示对手财务明细」「快速动画」两个开关 → **「📖 游戏规则 · 如何跳出老鼠赛跑」**（默认展开，随规则版本同步切换门槛倍数与文案）→ 开始游戏。

**顶栏**：`☰` 菜单 · 轮次/年龄胶囊 · `🔄` 重置游戏 · 主题切换 · 规则速查

**抽屉菜单**：财务报表 · 玩家一览 · 规则速查 · 信用贷/还款 · 玩家间交易 · **📊 本局复盘报告** · 切换主题 · **🏳️ 主动认输** · 重新开始

**复盘报告底部**：**「⬇️ 导出分析」（Markdown，含全部参与者的维度数据与分析结论）** 与 **「⬇️ 导出 JSON」（结构化数据）**；战绩页同样有导出入口。

**右侧面板四个标签页**：财务（实时收入支出表 + 资产负债表 + **出圈进度与社会等级**）· 日志 · 规则 · 设置

**主操作区**：屏幕上任何时刻只有一个主操作 —— 未移动时是「掷骰子（N 粒）」，卡片结算中置灰为「处理卡片中…」，已移动且结算完则升为「结束回合 · 轮到 X」；正上方常驻回合状态条。

**键盘**：`空格` 掷骰 / 结束回合，`Esc` 关闭弹层。

## 架构说明

### 分层与依赖方向

```
数据层  data-*.js          ← 纯数据，只往 window 上挂常量
   ↓
逻辑层  engine.js          ← 纯函数引擎，不碰 DOM；只依赖数据层
        engine-actions.js  ← 操作层，读写引擎状态；只依赖引擎
   ↓
表现层  ui-core.js         ← 通用 UI 原子（弹层 / Toast / 表单 / 报表渲染）
        ui-pending.js      ← 卡片结算弹层
        ui-summary.js      ← 复盘报告
        ui-game.js         ← 主界面与回合流程（唯一持有 Game 状态的地方）
   ↓
引导层  main.js            ← 绑定启动，无业务逻辑
```

**引擎与 UI 完全解耦**：`engine.js` 内部没有任何 `document` / `window` 调用，可以单独在 Node 里 `eval` 起来跑对局（本项目的自动化验证就是这么做的）。

### 社会等级评估（`UiSummary.socialClassOf`）

用两条**真实的轴**定位玩家所处的层级，而不是按结局排名 —— 现实中决定一个人在哪一层的，
恰恰就是「对工资的依赖程度」与「扛得住多久的意外」：

| 轴 | 游戏内的度量 |
|---|---|
| 对工资的依赖程度 | 被动收入 ÷ 出圈门槛（覆盖度）—— 与报告里的「出圈进度」**同一口径** |
| 扛得住多久的意外 | 应急金 = 现金峰值 ÷ 月总支出（能撑几个月） |

| 等级 | 名称 | 判定条件 |
|---|---|---|
| L7 | 人生赢家 | 本局获胜 |
| L6 | 财务自由 | 已出圈，或被动收入已超过门槛 |
| L5 | 临门一脚 | 覆盖度 ≥ 80% |
| L4 | 稳健中产 | 覆盖度 ≥ 50% |
| L3 | 小有积累 | 覆盖度 ≥ 25% |
| L2 | 温饱有余 | 应急金 ≥ 3 个月支出 |
| L1 | 月光无余 | 未出局，但应急金不足 3 个月 |
| L0 | 入不敷出 | 已破产出局，或月现金流为负且无缓冲 |

> ⚠️ **低三层用「应急金」而不是「净资产」做门槛。** 这个游戏里每个人的初始净资产都被房贷拖成负数
> （现金 + 资产 − 剩余本金），拿它当「扛不扛得住」的信号，会把所有刚开局的人一律打成最底层；
> 而「能撑几个月」才是真实的抗风险刻度。

每一级都会给出三样东西：**判定依据**（4 项可自行核对）、**距离上一级的达成度**，
以及 3 条**针对该层级**的财商手段（回答的是「怎么往上走一层」，与「出圈诊断」那份结构性复盘分工不同）。

**对局中随时可见**：财务面板的「社会等级」区块随每次操作重算 —— 阶梯位置、等级名称、
距上一级的达成度都在那里，**不必等到对局结束，也不必打开复盘**。
它与复盘报告读的是**同一份评估**（`UiSummary.socialClassOf`，口径只有一处），
否则迟早会出现「面板说 L4、复盘说 L5」这种自相矛盾。

### 消费升级：地位的隐性成本（`LIFESTYLE`）

**规则一句话**：意外支出的 **实付金额 = 卡片标价 × 消费档次系数**，系数由社会等级决定。

**触发条件**：不是「抽到某张卡」才触发，而是**持续生效** —— 只要社会等级在某次操作后变化，
下一张意外支出卡就按新系数计价（等级判定见上一节：被动收入覆盖度 + 应急金）。

| 等级 | L0 | L1 | L2 | L3 | L4 | L5 | L6 | L7 |
|---|---|---|---|---|---|---|---|---|
| 消费档次系数 | ×1.00 | ×1.10 | ×1.25 | ×1.45 | ×1.75 | ×2.05 | ×2.40 | ×2.75 |

**为什么是这条曲线**：现实参照是「车价翻 5 倍，保养费大约 ×2—3」。消费档次不会因为你多赚一笔钱
就跳一档，但会持续爬升。每一档都配了一句可对照的现实解释，**在弹层里直接展示** ——
避免「凭空多收钱」的观感。

**合理整合进经济系统的三个关键决定**：

1. **按卡片敏感度分两类承接**（卡片的 `scale` 字段）
   - `scale:'life'` 消费升级型（修车 / 换车 / 房屋 / 出游 / 培训）→ **全额**承接系数
   - `scale:'basic'` 基础型（税费 / 罚款 / 医疗 / 人情）→ 只承接 `basicDamp`（25%）的比例

   > 否则「补缴个税」也会随豪车一起涨价，不合逻辑。22 张意外支出卡已全部标注。

2. **同时放大「一次性成本」与「每月维护成本」**（卡片的 `cost` 与 `extraPay`）

   > 这才是「持有成本」的真实形态：豪车不只是买得贵，而是保险、保养、配件持续更贵。
   > 例：L4 抽到「购置度假房产」，标价 ¥12,000 → **实付 ¥21,000**，且每月额外支出 ¥300 → **¥525**。

3. **只作用于意外支出，不作用于基础生活支出**

   > 基础支出反映「你要活下去」，意外支出反映「你维持这个档次要付出什么」。
   > 若把系数也乘到基础支出上，会和既有的「支出随人生阶段浮动」互相叠加、变成双重计费。

**可解释性是这条规则能被接受的关键**：

- 弹层把账摊开给玩家看：**档次 → 系数 → 卡片标价 → 档次加成 → 实付**，并附该档位的现实解释
- **金额在落格时锁定**并存进 `pending`，弹层与扣款读同一个数 —— 不允许界面自己再算一遍
- 卡面显示**实付金额**；也因此把 22 条硬编码了金额的备注改写成不含金额的描述，
  否则「备注写 ¥200、需支付写 ¥350」会让人以为系统算错了
- 财务面板常驻显示当前系数；复盘报告的判定依据里也列出「消费档次 ×1.75」
- 因档次多付的部分**单独记账**（`stats.doodadTierPaid`），可以回答「这条规则一共让我多花了多少」

**它的用意**：中高等级会额外拿到一条建议 —— 让资产表以**生息资产**（存款 / 基金 / 股票，不产生维护成本）为主，
把**消耗型资产**（豪车、豪宅、奢侈品）控制在必要范围内。
这才是这条规则真正要教的东西：**富人的风险不是买不起，而是养不起。**

### 导出（Markdown / JSON）

复盘报告底部与战绩页各有导出入口。两种格式共用 `analyzeAll()` 的分析结果，
**保证两份文件说的是同一套数字**（两处各算一遍，迟早会对不上）：

- **Markdown** —— 按人分节，每位参与者一段：基本信息 / 关键指标 / 维度评分（6 维含加权总分）/
  社会等级评估（判定依据 + 提升手段）/ 出圈诊断与改进建议 / 下一局行动清单 / 关键决策时间线
- **JSON** —— 同源的**结构化数值**（指标为 `number`，可直接二次计算），含逐轮财富走势与节点时间线

文件名形如 `现金流复盘_101_年龄模式_第45轮_20260920-0936.md`；纯前端 Blob 下载，`file://` 下同样可用，不需要任何后端。

## 设计系统

Apple 简洁风格，全部令牌集中在 `css/base.css` 的 `:root` 与 `html[data-theme]` 两处。

| 类别 | 浅色 | 深色 |
|---|---|---|
| 页面底 / 卡片 | `#f5f5f7` / `#ffffff` | `#000000` / `#1c1c1e` |
| 主文字 / 次级文字 | `#1d1d1f` / `#6e6e73` | `#f5f5f7` / `#98989d` |
| 强调色 | `#0071e3` | `#0a84ff` |
| 功能色 | 绿 `#34c759` 红 `#ff3b30` 橙 `#ff9500` 紫 `#af52de` 青 `#5ac8fa` | 对应深色变体 |
| 圆角 | `--r-xs 6` / `--r-s 10` / `--r-m 14` / `--r-l 20` / `--r-xl 26` / `--r-pill 980` | 同 |
| 动效 | `--ease cubic-bezier(.32,.72,0,1)`，按压 `scale(.965)`，180—360ms | 同 |
| 分层 | 仅 3 级投影 + 1px 发丝分隔线；顶栏与操作坞用 `backdrop-filter: blur(20px) saturate(180%)` | 同 |

命名约定：令牌层（`--on-surface` / `--sep` / `--accent`）→ 基础层（Reset / Typography）→ 组件层（`.btn` / `.cardface` / `.rowlist` / `.segmented` / `.pick`）。

约定：**行内边距由「行」自己提供，分组容器不加内边距**（`.rowlist > * { padding-left/right: 14px }` 是兜底）。

### 2. 无头浏览器驱动脚本（本项目的主要验证手段）

原理：把一段探针脚本注入 `index.html` 的副本，用无头 Chrome 跑真实点击，最后把结果写进一个 `<pre id="DIAG">`，再从 `--dump-dom` 里抽取。

```bash
cat > __probe.js <<'EOF'
window.addEventListener('load', function(){
  setTimeout(function(){
    window.UI.setTheme('dark');
    window.startGame({rule:'101', mode:'age', count:4, names:['P1','P2','P3','P4'], showAll:true});
    setInterval(function(){
      /* 1) 有弹层时，先把弹层推到底 */
      var mh = document.getElementById('modalHost');
      if(!mh.hidden){
        var pick = document.querySelector('#modal .pick:not([disabled])');
        if(pick){ pick.click(); return; }                 /* 牌堆选择器没有 foot 按钮，必须单独处理 */
        var btns = document.querySelectorAll('#modal .modal__foot button');
        for(var i=0;i<btns.length;i++){
          var b = btns[i];
          if(b.disabled) continue;
          if(b.hasAttribute('data-ok') || b.hasAttribute('data-pass') || b.classList.contains('btn--primary')){ b.click(); return; }
        }
        return;
      }
      /* 2) 没弹层时按回合推进：结束回合 → 掷骰 */
      var end = document.getElementById('btnEndTurn');
      if(!end.hidden){ end.click(); return; }
      var roll = document.getElementById('btnRoll');
      if(!roll.disabled){ roll.click(); }
    }, 120);
    /* 3) 到点把状态写进 #DIAG 供 dump-dom 抽取 */
    setTimeout(function(){
      var g = window.Game.g;
      var d = document.createElement('pre'); d.id = 'DIAG';
      d.textContent = '第 ' + g.round + ' 轮 / ' + window.Engine.ageOf(g) + ' 岁 · '
        + document.getElementById('turnState').textContent;
      document.body.appendChild(d);
    }, 15000);
  }, 300);
});
EOF

python3 - <<'PY'
h = open('index.html', encoding='utf-8').read()
open('__probe.html', 'w', encoding='utf-8').write(h.replace('</body>', '<script src="__probe.js"></script>\n</body>'))
PY

"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --no-sandbox --disable-gpu --allow-file-access-from-files \
  --window-size=1440,900 --virtual-time-budget=30000 --dump-dom \
  "file://$PWD/__probe.html" 2>/dev/null \
| python3 -c "import sys,re,html; d=sys.stdin.read(); m=re.search(r'<pre id=\"DIAG\">(.*?)</pre>', d, re.S); print(html.unescape(m.group(1)) if m else 'NO DIAG')"

rm -f __probe.js __probe.html        # ⚠️ 验证完必须清理，别把临时文件留在仓库里
```

**驱动脚本的三个必踩坑**（都已在实践中遇到）：

1. **牌堆选择器没有 `foot` 按钮**（`.pick` 直接放在 modal body 里），必须单独处理，否则脚本会在第一步静默卡死、空转到超时。
2. **主按钮可能全被禁用**（例如现金不足时的公益捐赠），要加「点任意可用按钮 / 关闭弹层」的兜底分支。
3. **别用固定 `setTimeout` 对齐时序**，改写成「**等条件成立 → 执行动作**」的状态驱动，否则掷骰动画一慢就错位。

另外：`--user-data-dir` 复用 profile 做跨进程 `localStorage` 测试会让无头 Chrome 直接挂掉（exit 137）；需要验证「刷新后恢复」时，改为**单次加载内模拟刷新**（清空 `Game` 内存态 → 再调一次 `tryRestore()`），等价且稳定。

## 已知约束

这些都是当前实现里真实存在的边界，动手改之前建议先读一遍：

1. **数值是「对局平衡标定」，不等于现实**。金额量级沿用原版 1:1 映射为人民币，只调整了语义上明显脱离国内的项（信贷利率、支出科目、资产类型）。所以会看到「三甲医院医生月薪 ¥13,200」这类偏保守的数字；按真实收入/房价重算全表会连带影响出圈门槛与企业投资额，需要单独验证一轮平衡性。
2. **UI 与逻辑靠 ID / class 名硬契约绑定**，改类名不会报错，只会静默失效。
3. **202 的「破产后跳过回合 + 借贷限制」实际不生效** —— 因为当前规则是「破产即出局」，惩罚没有作用对象，仅保留在规则文案里。
4. **界面文案含 emoji**（📊 / 🏆 / 💀 等）。如果要按设计规范统一成 SVG 图标，需要做一轮图标替换。
5. **移动端是响应式降级**，不是独立设计：右栏下移、棋盘压缩、弹层转为底部 Sheet，未做专门的触控优化。
6. **没有测试框架，但有三个可直跑的验证脚本**（`test/`）：职业现金流扫描、长局回归、浏览器行为探针。
   它们零依赖、不需要 npm；浏览器探针仍需临时生成 `__probe.html` 并在用完后删除。
7. **`localStorage` 在隐私模式或配额超限时会静默降级**，此时刷新会回到开局页 —— 这是有意为之（不影响对局），但排查「进度丢了」时先确认这一点。
8. **棋盘坐标**依赖 CSS 的 7×7 网格与 `--g` / `--col` 计算，改棋盘尺寸时要同步检查 `RING_POS` 与 `game.css` 中 `.board` / `.board-center` 的公式。
9. **两条跑道共用一块屏幕**：`Game.boardView` + `Game.peeking` 是视图状态，一次只能显示一条跑道；
   两圈都有人的场景下，靠「跟当前玩家 + 可临时查看」来表达。若将来要做分屏 / 双方各自视图，改的是渲染层，不是引擎层。
10. **时间口径**：财务侧按「月」建模（发薪日发月现金流、开支是月供），而年龄模式里 **1 轮 = 1 岁**。
   贷款的一期因此定义在财务侧 —— **经过一次发薪日算一期**（一轮约 0.4 期）。
   平均每局只能还掉 20 期左右，所以长周期贷款（如助学贷款 200+ 期）在一局内靠月供还不完，
   **提前还款才是清债的主要手段**。这是有意的设计选择，不是 bug。
11. **「暂停回合」不删回合、只清行动权**：`Engine.markTurnPause(g)` 在每次交棒时结算 ——
   `skipTurns > 0` 的玩家会拿到 `pausedThisTurn = true`，回合**仍然属于他**（会正常轮到他、棋盘视图也会切到他），
   只是本回合不能掷骰 / 交易 / 借贷，界面给一张「⏸ 本回合暂停」提示卡点「交给下一位」。
   **不要退回「在 `nextPlayer` 里递归跳过该玩家」的写法** —— 两人局里那样会让对手连走三轮，
   看起来就像「已经出圈的那个人还在行动」，另一个人永远轮不到。
12. **`结束回合` 有 320ms 防连点**（`lastEndAt`）：它是「交棒」动作，双击会一次吃掉下一位的整个回合。
13. **人生模拟的参数是「对局平衡标定」，不等于现实**：`SALARY_CURVE` / `LIFE_STAGES` / `ENERGY` / `UNEMPLOYMENT`
    的取值一律取真实区间的**下沿**（例如收入峰值 1.35 倍，而真实职场可达 1.5—2 倍），
    目的是在不破坏原版平衡的前提下引入时间与精力压力。
    **改动这些参数后必须重跑两张表**：全职业 × 全年龄现金流扫描、以及长局回归 ——
    首版就曾因「赡养用固定金额」导致全员在中年必然破产（低收入职业被扣掉半个收入）。
14. **未建模的真实缺口**（已知但本次未做，详见 `docs/人生模拟改造说明.md` 第六节）：
    退休后收入断崖（60 岁后仍按在职收入计算）、子女成年后养育支出不下降、
    精力维护成本对资产数量是线性的（现实中 5 套房产的管理成本不是 1 套的 5 倍）。
