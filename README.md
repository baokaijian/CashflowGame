# 现金流游戏 · 中国本土版

围绕“老鼠赛跑 → 财务自由圈”的浏览器回合制游戏。提供 **101 基础版、202 进阶版**，以及年龄、单人、无限三种模式；职业、投资机会和生活事件采用中国本土语境。玩家需要同时管理现金、负债、家庭支出和精力。

**[在线游玩](https://baokaijian.github.io/CashflowGame/)** · 纯静态 HTML / CSS / JavaScript，无后端、无构建依赖。多人模式为同一设备轮流操作。

本文按当前代码整理（2026-09-26）。金额、收益率、养老金及授信参数服务于游戏平衡，不代表现实价格或制度。

## 开始游戏

可以直接访问在线版，或下载仓库后用浏览器打开 `index.html`。本地开发建议在仓库根目录启动静态服务：

```bash
python3 -m http.server 8080
```

随后访问 `http://localhost:8080`。游玩无需 Node、npm 或打包工具；界面需要支持 `color-mix()` 和 `:has()` 的现代浏览器。

开局选择规则版本、模式、玩家与梦想，然后按页面提示掷骰、处理事件、结束回合。菜单提供财务报表、玩家一览、规则速查、贷款管家、玩家间交易、复盘报告、主题切换、主动认输及重新开始。

- 空格键：在没有弹层时掷骰或结束回合。
- Esc：关闭允许关闭的弹层；必须完成的事件不能直接跳过。
- 两条跑道共用棋盘区域，默认跟随当前玩家，也可临时查看另一圈。
- 页面支持浅色 / 深色主题和响应式布局。

在线版、本地服务和直接打开文件使用不同的浏览器存储空间，存档不会自动互通。

## 模式与结算规则

### 三种模式

| 模式 | 时间与退休 | 对局结束 |
|---|---|---|
| 年龄模式 | 20 岁开始，各玩家独立计龄；不启用单人退休规则 | 有玩家达成胜利条件，或所有仍在局内的玩家各自到 65 岁后按账面净资产排名 |
| 单人模式 | 固定 1 人，20 岁开始，61 岁切换退休状态 | 出圈、圆梦等成就记录达成年龄，继续玩到 65 岁；破产或认输可提前结束，最终给出人生评级 |
| 无限模式 | 不设终龄，年龄仍随结算日增长 | 达成胜利条件后结束 |

### 一次结算日就是一年

**每经过或落在一个发薪日 / 分红日，只结算一年的收支，并长一岁。** 行动轮次不等于年龄；没有经过结算日就不长岁，也不会积欠或补发。

每次先按当前账本结算 12 个月收支，再摊还 12 期贷款、推进年龄及家庭状态。一次移动如果经过两个结算日，就分别结算两年；前后两年的金额可能因还贷、退休等变化而不同，提示显示逐年明细与合计。

内圈有 3 个发薪日，外圈有 4 个分红日。到达终龄立即停止继续移动；最后一年的现金缺口须先处理，终局不额外补结。正常从 20 岁走到 65 岁共结算 45 年。

详见 [结算步长与发薪日密度](docs/结算步长与发薪日密度.md)。

### 101 与 202

| 项目 | 101 基础版 | 202 进阶版 |
|---|---|---|
| 出圈条件 | 被动收入严格大于总支出 × **1.5** | 被动收入严格大于总支出 × **2.5** |
| 投资机会 | 小额理财、大额置业 | 杠杆交易、大额现金流；机会格还会抽取行情卡 |
| 交易工具 | 做多投资 | 增加融券做空、期权 |
| 房产合作 | 独立购买 | 支持联合购买；单人由机构承接合作 |
| 开局配置 | 职业卡 | 职业卡 + 随机投资组合卡 |
| 行情政策卡 | 16 张 | 42 张，抽满 25 张重洗 |
| 自由圈企业 | 购买企业 | 另有特许经营与收购玩法 |

当前数据包含 12 个职业、10 张初始投资组合卡、6 个梦想、7 家自由圈企业，以及合计 132 张投资、行情和意外支出卡。

出圈后进入财务自由圈，获得出圈资金，收入改为基础分红与自由圈企业收入；生活支出及既有债务仍需支付。购买自己的梦想，或自由圈新增企业月收入达到 **¥20,000**，可以达成胜利条件；202 另有最后一位存活玩家获胜的规则。单人模式将这些结果作为成就记录，继续人生进程。

## 当前已实现的功能

### 家庭收支与生活变化

工资、日常支出、赡养压力和精力随年龄变化；失业会进入求职期，精力不足会影响工作表现，健康危机还会增加临时负担。

| 项目 | 当前规则 |
|---|---|
| 子女养育 | 逐个记录子女年龄；0—17 岁按基准支出，18—21 岁减半，22 岁起归零；终身最多 3 个子女 |
| 缴费年数 | 仅在实际完成年度结算且仍有工资、在职、未退休、未出圈时累计 |
| 单人养老金 | 基础工资 × 45% × `min(1, 缴费年数 / 41)`，不受低精力工资折减影响 |
| 退休医疗 | 单人 61 岁起按基础工资的 2% 计月支出，此后每增一岁增加 0.5 个百分点，最高 6%；健康危机费用另计 |
| 住房预算 | 以职业基础工资的 11% 为基准，随人生阶段调整，已有房贷月供抵扣预算 |
| 用车预算 | 以职业原车贷月供的 50% 为基准，随人生阶段调整，已有车贷月供抵扣预算 |
| 消费预算 | 保留日常消费，并以职业原信用卡月供的 50% 作为持续消费预算基准，已有信用卡月供抵扣 |

生活预算只补已有支出不足的部分，避免重复收费。还清车贷和信用卡仍会改善现金流，但不会让用车和持续消费成本消失；补足额同时进入年度支出和出圈门槛，不算作贷款月供。自由圈也使用这套预算，先调整生活档次再抵扣月供，避免“还款后支出反而增加”。

旧存档中没有年龄记录的子女保留原支出，从更新后开始计龄；缺失的历史缴费年数只能估算，并带有估算标记。迁移不改写历史现金收支。

详见 [家庭收支与人生变化](docs/家庭收支与人生变化.md)、[持续生活预算与还贷](docs/持续生活预算与还贷.md)。

### 资产、报价与交易

游戏区分**取得成本、参考估值、抵押权益、实际成交款**，它们有不同用途：账面净资产用于排名，参考估值用于观察资产变化，抵押权益用于授信，成交款决定实际现金变化。

- **股票报价**：同一证券共用最新报价；已有报价时不再额外叠加周期估值。
- **房产融资**：正常购买登记本人取得成本、首付、持仓份额及项目融资余额；租金净现金流已扣项目利息。
- **共有房产出售**：整套报价先乘本人份额，再扣对应项目融资与费用，得到本人净回款；负权益出售需要补足现金。
- **持仓定位**：房产交易按持仓编号定位，避免筛选列表下标指向另一套房产。
- **持续存在与回购**：房产有稳定实体编号。出售后可从下一轮起再次挂牌，在投资机会中买回同一套房产；再次买入生成新的持仓记录。
- **玩家间房产转让**：约定价是股权款，买方同时承接该房产对应融资；与卖给市场后再挂牌的流程不同。
- **抵押明细**：贷款页逐项列出已持有资产。待买商铺不会在成交前变成抵押物；房产可抵押权益扣除对应项目融资，最低为零。
- **急售与破产处置**：按相应处置折扣计算，房产仍需扣还项目融资；参考净资产保留负权益，不能用抵押权益的零下限掩盖亏损。

参考估值会变化，某次行情卡给出的成交报价则对应当次机会，二者不保证在所有时点相等。初始“老破小出租房”组合已统一为项目融资：月租金 ¥708，扣月息 ¥492 后净现金流 ¥216，不再另记其他负债。可识别旧档按实际剩余余额迁移，不补发或追扣历史现金；来源混合或凭据缺失的旧债保留原账，并在财务页提示待核对。股票和企业协议转让已按成交款建立买方成本及新持仓编号，企业保留累计使用年数与经营参数；历史交易没有可靠成交记录时不猜测重建成本。

详见 [资产报价与交易结算](docs/资产报价与交易结算.md)。

### 经营精力与机构合作

持有资产的管理成本已按经营类型和组合规模区分。车位、普通住宅、老旧住宅、商铺及不同企业使用不同维护参数；同类组合有管理效率收益，项目过多又会增加协调负担，已不再简单按“资产数量 × 单项成本”计算。

实业采用不同折旧速度与残值下限，并按实际持有年数计算。残值是模型估值的下限，不是市场保底收购价；行情报价仍可能更低。

单人 202 联合购房可以比较三种机构：

| 机构 | 机构出资占比 | 玩家的主要取舍 |
|---|---|---|
| 共担资本 | 50% | 标准共担方案，不收管理费 |
| 资金后盾 | 70% | 自己承担较少首付，也只享有较小产权份额 |
| 运营管家 | 50% | 减少考察与维护精力，从玩家正现金流中收取 20% 管理费 |

合同随持仓保存，收费进入净现金流；旧档中没有合同的共有资产不会凭空新增费用。机构已有经济条件差异，但还没有自主议价、退出或违约行为。

详见 [经营差异与机构合伙](docs/经营差异与机构合伙.md)。

### 贷款与现金缺口

贷款管家管理住房、助学、车贷、信用卡、其他分期和银行信用贷。分期贷款按计划摊还；提前还款支持相应的结清、缩期或降低月供方案，并显示本金、违约金及实际支出变化。

授信综合收入、现有月供、抵押权益、信用状况、多类借款、近期借款次数与额度使用情况。失业和退休会影响收入侧授信，但抵押资产仍按自身情况评估。“先贷款”使用收入或已持有资产补足现金，不是把尚未购入的房产提前抵押。

年度结算出现现金缺口时，须通过允许的借贷、出售资产等方式处理；无法解决则破产出局。当前没有破产后重新入场的机制。

## 存档与复盘

游戏通过浏览器 `localStorage` 自动保存最近一局，并记住开局配置和主题。恢复会兼容旧档中的时间、资产、家庭与经营字段；生活预算调整只影响未来账本，不追补历史费用。

复盘可查看财富走势、成就、人生评级等，并导出 **Markdown 或 JSON 报告**。这些是分析报告，**不是完整存档，不能导入继续游戏**。年龄模式排名采用账面净资产；单人人生评级结合达成年龄与最终社会等级，是游戏内评价。

保存边界：

- 没有多存档槽、账号同步、云存档或存档导入界面。
- 清理网站数据、更换浏览器或地址会使原存档不可见；隐私模式、空间不足或存储被禁用时可能无法保存，当前缺少可靠的保存失败提示。
- 自动保存采用短延迟合并，并在页面离开时尝试写入；不能保证浏览器异常关闭前的最后一步已落盘。
- 内存日志最多保留 300 条，存档日志最多 80 条，财富轨迹最多 60 个采样点，因此复盘不是完整交易流水。
- 固定种子支持不中断运行时的回归复现；恢复存档后不会恢复随机数生成器内部状态，后续掷骰与重洗牌不保证延续原随机序列。

### 尚未完整建模的部分

| 领域 | 当前边界 |
|---|---|
| 房产项目融资 | 通常为持有期付息、出售时还本，余额不逐年摊还；不等同于贷款管家中的家庭住房分期贷款 |
| 房产交易平衡 | 份额、融资和资本利得公式已统一，但高收益行情报价的分布仍需进一步复核；能再次挂牌不等于有完整的买卖双方撮合市场 |
| 财务自由圈 | 工资和养老金不叠加到分红账本属于现行规则；基础分红锁定且原资产仍可出售造成的收益归属问题已列入上述待修复项 |
| 家庭与退休 | 未建立配偶收入、婚姻变化后的完整家庭账本；养老金只采用缴费年数比例，没有真实缴费账户、最低缴费门槛和地区政策差异 |
| 生活选择 | 住房、用车和消费预算由职业基准与人生阶段推导；尚不能主动降档或卖车降低预算，也没有独立的车辆更新储蓄账户 |
| 经营与折旧 | 已区分经营类型，但同类型、同持有年数的资产仍缺少个体维修质量差异；没有完整的企业经营失败与归零事件链，残值下限不代表保本 |
| 机构合伙人 | 有出资、精力与收费差异，尚无主动退出、违约、议价或控制权博弈 |
| 征信 | 当前是本局借款行为模型，没有真实跨机构查询、对外担保及完整征信记录 |
| 旧档迁移 | 无法准确重建缺失的出生、缴费、交易和报价历史；兼容值只保证后续规则可运行，不能恢复完整历史账本 |

### 产品与平台边界

- 多人局是本地轮流操作，没有联网房间、远程同步或自动行动的 AI 对手；单人的机构也不是会独立走棋的玩家。
- 移动端采用响应式布局，没有独立的移动端交互方案；两条跑道一次只显示一条。
- 破产即出局。新规则说明已统一为出局；存档中的历史日志可能仍保留旧惩罚措辞，不构成重新入场规则。
- 价格周期与多项人生参数采用确定性曲线或预设系数，不能作为真实人生或投资结果预测。
- 存档可靠性、日志截断和随机序列恢复限制见 [存档与复盘](#存档与复盘)。

脚本通过全局模块连接，按 `index.html` 中的数据 → 引擎 → 动作 → 界面 → 启动顺序加载。引擎与数据可脱离 DOM 运行，界面依赖元素 ID、class 和事件约定；修改标记或加载顺序时须同步检查调用方。

### 维护约定

1. **时间与金额同源**：年龄读玩家年龄，不能从轮次推导；界面读取引擎已生成的结算明细，不能重新发薪。年度结余使用 `Engine.settleCashflow`，出圈门槛使用 `Engine.escapeTarget` / `Engine.escapeMargin`。
2. **预算只补差额**：住房、用车和消费预算不能再叠加完整收费；自由圈先放大预算再抵扣月供。还款预览必须与执行后账本一致。
3. **资产身份稳定**：新增买入路径须登记取得时间及经营参数；房产登记实体与持仓编号，交易不能用筛选后的下标定位原资产。
4. **交易先验证再改账**：拒贷、拒绝出售或补款不足时不得留下部分现金、负债或产权变更。授信展示和实际借款共用 `Engine.creditProfile`。
5. **参数联动修改**：首付、融资、租金、净现金流和卡片备注要一起复核；经营参数、资产类别映射和迁移路径也须同步。`SOLO_STAGES` 仅负责叙事，不存业务数值。
6. **随机入口与暂停规则**：新增随机行为接入游戏随机源；暂停回合保留交棒过程，不能递归跳过玩家；结束回合保留防连点保护。

### 验证入口

项目没有 npm 依赖或测试框架。现有 **21 个 Node 验证脚本**，覆盖职业收支、长局、单人、时间与发薪、报价与交易、贷款、家庭、经营、生活预算及资源版本；另有浏览器行为探针验证真实按钮、弹层与恢复流程。

运行全部 Node 验证：

```bash
for file in test/*.js; do
  [ "$file" = "test/browser-behavior.js" ] && continue
  node "$file" || exit 1
done
```

按修改范围选择相关验证，交互变更还需运行浏览器探针。具体运行方式与覆盖说明见 [验证脚本说明](test/README.md)；其中早期的参数示例和断言数量可能随实现变化，以脚本内容及实际输出为准。

修改 JavaScript 或 CSS 后，发布前更新资源版本并检查：

```bash
node tools/version-assets.js
node test/asset-version.js
```

资源 URL 使用内容版本，减少发布后沿用缓存文件的情况；启动时另检查发薪规则标识，但这不是所有脚本版本组合的完整兼容性校验。仅修改 README 不需要重生成资源版本。

`tools/calibrate-prices.js` 和 `tools/rebalance-returns.js` 会改写卡片数据，不是启动步骤。调参后需复核备注与金额，并运行价格、投资回报、出圈难度和长局验证。
