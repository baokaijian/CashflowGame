> 本文记录**待决策项 №1 的落地**：让「金钱时钟」跟上「年龄时钟」，并配一轮价格标定。

## 一、核心规则

### 1.1 结算覆盖「自上次结算以来经过的年数」

```js
// engine.js · movePlayer
const since = p.settledAge;              // 上次结算时的年龄（开局为 startAge − 1 = 19）
const due   = ageOf(g) - since;          // 已经过去了几年
if (due <= 0) { /* 本年的账已结过 → 略过，但仍记一笔好让弹层说清 */ return; }
const amount = annual(monthly) * due;    // 领 due 年的钱
p.settledAge = ageOf(g);
amortize(g, p, due);                     // ★ 领几年就还几年
```

| 情形 | 行为 |
|---|---|
| 20 岁第一次踩到发薪日 | 结算 1 年 |
| 24 岁再踩到（中间 4 年没踩到） | **一次结算 4 年** |
| 同一年内再踩到 | `due <= 0` → 略过，弹层说明「本年已结」 |
| 一次移动经过 2 个发薪日 | 第 1 个结算、第 2 个略过（一年只结一次账） |

### 1.2 现实依据

「一年只结一次账」本来就是现实：**发薪日只是你领钱的时点，不是时间的刻度**。
如果隔了 4 年才走到发薪日，那就该一次领 4 年的钱 —— 而不是每年凭空多出一次收入。

反过来，「每个发薪日各结一年」隐含了一个错误设定：**时间由格子决定**。
它派生出两个荒谬推论 —— 掷骰运气差的人一生收入更少（虽然活得一样久），
以及走得快的人更容易出圈（因为踩到的发薪日更多）。

### 1.3 调整后的效果（实测）

| 指标 | 改前（固定 1 年） | 改后（结经过的年数） |
|---|---|---|
| 一生结算年数（单人 101） | 约 20 年 | **43—45 年** |
| **结算覆盖率** | **44.4%** | **93.3%—100%**（多数局 95%+） |
| 发薪次数 | 19—21 次 | 19—21 次（**不变**） |
| 单次金额 | 固定 1 年 | 1—4 年不等 |
| 贷款本金 | 一生只摊还约 20 年 | 摊还约 43 年（多数贷款在游戏中结清） |
| 期末负债（4 人局样本） | 数万 — 数千万（含信用贷螺旋） | 多数为 0，少数数万 |

**一笔实测明细**（单人 101，种子 7）：

```
19 岁开局（尚未结过账）
20 岁首次结算：1 年      → ¥15,192
24 岁再结算：  4 年      → ¥60,768      「自 20 岁以来经过的 4 年一次结清」
同岁再踩一次： 0 年      → ¥0           「本年（24 岁）的账已经结过了」
```

### 1.4 前后差异

| | 改前 | 改后 |
|---|---|---|
| 一生的总收入 | 只领到 44.4% 的年头 | 领到 93—100% 的年头 |
| 与年龄的关系 | 两个互不相干的时钟 | **刻度一致**（每游戏年结算 1 年） |
| 「踩到发薪日」的意义 | 每次都是一年的钱 | 钱一样，但它决定**何时**拿到 |
| 掷骰运气的影响 | 直接影响总收入（不合理） | 只影响「什么时候拿到」（合理） |

## 二、边界与仍存在的残差

### 2.1 残差：最后一次结算到退休之间的尾巴（0—3 年）

若最后一次踩到发薪日是 59 岁，那 60—64 岁这 5 年的账就没有被结算（覆盖率 89%）。
实测各局为 93.3% / 95.6% / 95.6% / 97.8% / 100%。

**不打算消除它**，理由是：要 100% 就必须让「每个游戏年都触发一次结算」，
那就等于把发薪日降级成纯粹的展示格（棋盘上 3 个发薪日格失去意义）。
当前口径保留了「踩到才结算」的仪式感，代价是平均数年的尾巴 —— 这笔交易划算。

> 若将来要彻底消掉：在轮次边界为「本年未结算」的玩家补一次结算。
> 难点是负结余年份需要走「入不敷出」弹层，而轮次边界不属于任何玩家的回合。

### 2.2 同一次移动经过多个发薪日：只有第 1 个发钱

这是「一年只结一次账」的直接推论，不是漏发。弹层会明说：

> `本回合经过 2 个发薪日，其中 1 次因本年已结而略过`

**这条把审计里发现的「一回合可结算 3 年而年龄只 +1」消除了** —— 现在单次移动最多结算 1 年。

### 2.3 摊还与结算必须同步

`amortize(g, p, years)` 现在接收年数。若领 4 年却只还 1 年，负债会被系统性低估。
财务自由圈的「分红日」也补上了摊还 —— 旧版只有内圈发薪日摊还，**出圈后负债会冻结**。

## 三、价格标定

### 3.1 为什么必须做

方案 A 让**每个游戏年沉淀下来的净现金**变成原来的 **2.15 倍**
（覆盖率 95.6% ÷ 44.4%）。而资产价格是绝对值 ——
不换算的话，同样一笔钱能买到 2.15 倍多的资产，出圈与财务自由圈的目标都会唾手可得。

### 3.2 为什么只换价格、不换收益

| 类别 | 是不是「存量货币」量 | 处理 |
|---|---|---|
| `price` / `cost` / `dp` / `strike` / `premium` | 是 —— 「要用多少钱去买」 | **× 2.15** |
| `cf` / `rent` / `interest` | 否 —— 「一年能产生多少」 | 不动 |
| `pct` / `rate` / `min` / `max` | 否 —— 比例与数量 | 不动 |

效果等价于「**资产变贵了、收益率被压缩**」—— 这也正是货币变多时真实经济体的样子。
实测：7 家财务自由圈企业的收益率从约 6% 压到约 2.8%，整批一致。

### 3.3 换算范围（实测数字）

```
node tools/calibrate-prices.js 2.15
→ 换算字段 115 处 | 同步备注 96 条 | 自由圈企业 / 梦想 13 处

  DECK_SMALL      字段 18 · 备注 14      DECK_CAPGAIN   字段 23 · 备注 16
  DECK_BIG        字段 16 · 备注 12      DECK_CASHFLOW  字段 14 · 备注 10
  DECK_MARKET_101 字段 13 · 备注 13      DECK_MARKET_202 字段 31 · 备注 31
```

**买卖两侧一起换**是硬要求：只换买入价会成为低买高卖的漏洞（因为市场收购价在另一副牌堆里）。
回归里有一条断言专门守它 —— 实测 5 组同名物业的收购价倍数为 ×2.08 / ×1.80 / ×1.82 / ×1.33 / ×1.22，全部 > 1。

**意外支出卡（`DECK_DOODAD_*`）刻意不换**：它是一次性的事件金额，与职业卡的收支刻度同源，
相对权重由「消费升级 × 消费档次」独立调节，不参与货币存量换算。

### 3.4 为什么写进数据文件，而不是做成运行时常量

价格字段有 **30+ 处读取点**（买入 / 出售 / 抵押 / 净资产 / 卡面展示 / 做空平仓 …）。
任何一处漏掉都会造成低买高卖。一次性写进数据后，所有读取点自动一致 ——
零代码改动、零遗漏风险。代价是需要在数据文件里记录推导过程（见 `window.PRICE`）。

### 3.5 ⚠️ 一个反直觉的实测结论：标定【不会】改变出圈时机

用会买入、会主动出圈的 AI 各跑 14 局（单人 101）：

| 价格系数 | 出圈率 | 出圈年龄中位 | 期末现金中位 |
|---|---|---|---|
| ×1.00 | 57% | 46 岁 | ¥1,099,246 |
| ×1.50 | 57% | 38 岁 | ¥1,415,481 |
| ×2.15 | 57% | 46 岁 | ¥805,930 |
| ×3.00 | 79% | 43 岁 | ¥1,138,180 |
| ×4.00 | 64% | 45 岁 | ¥1,011,080 |

**系数从 1.0 调到 4.0，出圈年龄中位数只在 43—46 岁之间摆动，落在样本噪声内。**

原因：出圈条件是 **被动收入 > 总支出**，而**总支出会随贷款结清而崩落**
（房贷还完后从 ¥3,000 掉到 ¥400—1,000）。此时**一件出租物业的月现金流（¥1,600—5,000）
就足以跨过门槛** —— 也就是说，约束是「什么时候抽到合适的卡」与「门槛有多低」，
而不是「攒首付要多少年」。价格只影响攒首付，所以调它几乎不动出圈时机。

**结论：价格标定解决的是「名义量随货币增量同步、买卖两侧不出漏洞、财务自由圈目标不贬值」，
它不是一个难度旋钮。** 想调难度要动的是门槛与卡片分布（见第五节）。

### 4.1 踩坑：取整单位设错会把期权抹成 0

标定脚本第一版把所有金额统一按「百元」取整，而期权的 `premium` 是 1.5—3.5 的**小数**、
`strike` 是 10—20 的**个位数** —— 于是 `strike` 与 `premium` 全部变成 **0**，
期权就成了「免费且必然行权」。现在取整单位按字段分档
（`price:1 / strike:1 / premium:0.1 / cost:100 / dp:100`），并在换算后加了一道
「归零即中止」的断言。

### 4.2 踩坑：替换金额时漏掉小数点

备注替换用 `[\d,]+` 匹配数字，遇到 `¥3.5` 只吃掉了 `3`，替换后变成 `¥7.5.5`。
改为 `[\d,]+(?:\.\d+)?` 并在落盘前校验「备注里不得出现 `数字.数字.数字`」。
