# 第四批：报价可达性、出圈奖励与财富轨迹

实施日期：2026-09-27。基线提交：`6c4282b`。本批完成修复排期的第四批审计及回归，不代表所有玩法策略已经达到最优平衡。

后续追加修复了租金行情及复盘收支口径，见 [追加核验](租金行情与复盘口径修复.md)。本文和配套数据保留第四批交付时的结果，不应视为后续版本实时胜率。

## 审计方法

新增 `tools/audit-balance.js`，使用真实引擎完成开局、掷骰、年度结算、贷款、筹资急售、投资、行情、出圈和自由圈事件。为 12 个职业各寻找 6 个自然开局种子，不手动替换职业账本；两版使用同一批种子。每版各执行持有、兑现两种固定策略，共 288 个情景；修复前后各跑一遍。

- 持有策略：主要购买产生正现金流的资产，202 大额房产可与标准机构合伙；不主动接受自愿行情报价。
- 兑现策略：同样买入现金流资产，另接受纯资本利得房产；房产只接受盈利报价，其他已有可交易持仓接受当期报价。行情冲击执行一次，202 投资机会中的交易按买入后进入行情页的顺序执行。
- 买入保留至少 ¥20,000 或 6 个月支出；缺口先尝试贷款，再按可变现款从小到大急售。自由圈选择现金可负担的企业，遇到本人梦想尝试购买。
- 两者都不操作期权、做空、主动回购或主动减少高维护资产，不声称代表最优玩家。观察上限 500 回合，达到上限的情景单列，不当成完整人生终局。

可复跑：

```bash
node tools/audit-balance.js --baseline 6c4282b --out /tmp/cashflow-balance.json
node test/balance-audit.js
node test/wealth-history.js
```

逐职业结果、所有种子、报价对应表及实际成交见 [审计数据](第四批平衡审计数据.json)。缺少本地基线提交时可省略 `--baseline` 运行当前版本。

## 确认并修复：202 的四张无对应标的报价

原 `m22 / m23 / m24 / m26` 分别报价“小区车位 / 小区车位 / 单身公寓 / 三居室住宅”。这些名称在 101 投资牌堆中存在，但 202 正常开局的组合和投资牌堆不能取得它们，因而无法形成正常买卖路径。旧报价不是“难遇到买家”，而是指错了本版交易对象。

改为给现有的郊区小地块、商业综合体商铺、仓储物流园提供买家：

| 行情卡 | 对应投资卡 | 整套买价 | 首付 | 整套报价 | 单次资本利得 / 首付 |
|---|---|---:|---:|---:|---:|
| m22 | cg15 郊区小地块 | ¥64,500 | ¥29,025 | ¥81,915 | 60% |
| m23 | cg15 郊区小地块 | ¥64,500 | ¥29,025 | ¥99,330 | 120% |
| m24 | cf3 商业综合体商铺 | ¥2,580,000 | ¥1,161,000 | ¥3,276,600 | 60% |
| m26 | cf8 仓储物流园 | ¥1,505,000 | ¥677,250 | ¥2,114,525 | 90% |

这些比例是游戏内的一次性报价档位，不是年化收益或现实价格判断。选择 60% / 90% / 120% 作为普通、较好、强势报价，使新增出口保留差异，又低于既有 202 长租公寓约 167%、写字楼约 139% 的首付收益。公式为 `整套报价 = 取得总价 + 标准首付 × 单次权益收益比例`，共有出售仍先按本人份额计算，再扣项目融资及费用。

卡片记录 `sourceCard` 和 `equityGain`，`tools/rebalance-returns.js` 同时重算报价和备注，避免未来调首付时再次脱节。两次重算幂等以及首付变化联动均有回归。

模拟中四张新报价分别实际成交 14、12、2、8 笔；不是只给持仓注入巨额现金验证。202 同次机会允许买入后接受行情报价，部分成交持有年数为 0，这些被保留在数据中，不能把收益解释成年化。

基线中 101 两策略各有 2 个情景达到 500 回合观察上限，因此表中称“观察末”，不将这些结果误称为 65 岁终局。排查确认是休养续期循环，修复后全部 288 个情景在上限内结束；202 两策略破产各 30 局。上述变化同时包含报价修复和休养修复，不能归因于某一个参数。以上样本是固定策略测试，不是玩家总体胜率估计。

### 为什么保留其他价格和出圈奖励

101 房产单次权益收益范围仍为约 74%—269%。高报价已在真实路径中成交，但需要取得相应资产并遇到报价，还要承担时间、精力和支出。当前证据支持修复交易对象，没有支持将整个牌堆统一降价；后续可用更多策略和种子评估。

一次性出圈资金继续为当时被动收入 × 100，未来分红继续取当前持仓，不重复领取或永久保留已售资产收入。修复后 101 两策略出圈奖励中位数分别为 ¥256,800 / ¥290,700，202 为 ¥1,136,300 / ¥988,600；出圈当刻都没有负的自由圈现金流。

202 中有 6 / 8 个出圈情景仅奖励就足以支付本人梦想，但需要落到对应格，且有家庭支出、税务、离婚等后续事件。最终持有 / 兑现策略圆梦为 0 / 1 局、企业成就为 1 / 3 局，不能把“奖励够买”视为“立即获胜”。本批没有据此削减奖励。202 长期高维护组合的经营风险及策略覆盖不足仍需持续观察。

## 审计追加修复：强制休养无限续期

基线 4 个情景停在 61 岁，达到 500 回合仍不能继续。当维护消耗高于康复期恢复速度时，强制休养的回合也会精力归零、再次触发危机，将暂停轮数重新设为 2；玩家每次刚结束休养又被续期，无法掷骰推进人生。

修复后休养期间仍扣维护精力、最低为零，医疗倒计时正常推进，但不重新触发健康危机来续期。两轮休养结束后恢复掷骰；正常行动回合若再过劳仍会触发危机，没有取消经营负担或额外发钱。旧存档保留剩余休养轮次，恢复后同样适用。多人轮转、真实按钮及原种子案例均有回归。

## 修复：财富轨迹与自由圈现金流

旧版每轮追加一个点、超过 60 点直接丢弃最早记录。288 个情景中 262 个丢掉了 20 岁开局点；修复后均保留。

现在仍每轮观察，但每个玩家按自己的年龄聚合：首个已知点独立保留，同龄后续采样只保留最新点。普通 20—65 岁人生至多 47 点；一次移动跨两年时未观察到的中间年龄不补造。无限模式超过 60 点时保留首个点和最新 59 点。每次观察仍更新峰值统计，不因合并遗漏同龄内已观察的峰值。

自由圈采样的月现金流改读 `settleCashflow`，与当前持仓分红及自由圈支出一致，不混入停领的工资。图表横轴按年龄间隔绘制，首点标签显示首点实际金额；旧版错误地把全段最低值标在起点。

## 旧档与验收边界

- 旧存档的已抽牌、剩余牌堆和锁定报价原样保留，不因更新改写待处理交易、历史现金或融资。新局使用修正后的四张报价；旧局不会自动换牌。
- 旧轨迹只合并现存记录，保留首个已知点及可恢复的峰值；丢失的早年记录不补造。历史现金流不能可靠重算，保留原值并在复盘显示兼容说明。
- 日志、里程碑与轨迹仍有容量上限，不是完整流水；本批没有增加云存档或联机交易。
- 28 个 Node 验证脚本、217 项浏览器断言通过。新增平衡与轨迹脚本各含 7 组回归，健康休养脚本包含 6 组；浏览器 Y / Z 组覆盖四张报价的真实卖出、年龄轨迹、复盘显示、存档恢复及休养后实际掷骰。原存档、随机、家庭、交易及发薪回归继续通过。
