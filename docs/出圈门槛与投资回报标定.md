# 出圈门槛与投资回报标定

> **时间规则更新（2026-09-22）**：现行规则为每个发薪日 / 分红日结算一年并长一岁，玩家独立计龄；回合不长岁，无积欠、略过或退休 / 终局补结。本文涉及旧时间口径和旧测试数量的内容保留为历史记录，当前实现以 [发薪日、年龄与年度结算](结算步长与发薪日密度.md) 为准。

> 解决的问题：**「出圈」太容易了。**
> 改造前 12/12 个职业全部出圈、中位年龄 **34 岁**、最快 31 岁 —— 一个人 30 出头就财务自由，
> 剩下的 35 轮人生没有任何张力。根因是投资机会的回报率是 **22%—45%**（投入口径），
> 这个数字在任何真实市场里都不存在，于是**一张卡就能覆盖全部生活支出**，门槛形同虚设。
>
> 可复跑：`node test/escape-difficulty.js`（30 项断言，退出码 0 = 全通过）。
> 重算工具：`node tools/rebalance-returns.js`（幂等，可从 `cost` 完整复算）。

---

## 一、核心规则

三处改动，互相咬合：

| # | 改动 | 从 | 到 |
|---|---|---|---|
| ① | **出圈门槛加入财务安全边际** | `被动收入 > 总支出`（101）/ `× 2`（202） | `× **1.5**` / `× **2.5**` |
| ② | **投资回报降到现实区间** | 投入口径 **22%—45%** | 住宅 **5.2%** · 商业 **7.3%** · 实业 **9%—11%** · 固收 **5.8%** |
| ③ | **首付比例修正到现实区间** | 住宅 **13.3%** · 商业 **8.3%—20%** | 住宅 **30%** · 商业 **45%** · 车位 **40%** · 法拍房 **100%** |

三者合起来的效果，用一个数字就能说明：

```
            改造前                              改造后
每 ¥1 月被动收入  住宅只需 ¥53.75 本金    →   需要 ¥231 本金（住宅）/ ¥164（商业）
```

**每元被动收入需要的本金上升到约 3—4 倍。**

## 二、现实依据

### 2.1 为什么 22.3% 不成立

改造前 `bg1 三居室住宅`：总价 ¥645,000、**首付 ¥86,000**、毛租金 ¥3,600/月、净现金流 ¥1,600/月。

把这条链拆开看：

| 指标 | 改造前的隐含值 | 中国现实 |
|---|---|---|
| 首付比例 | **13.3%** | 首套 20%—30%，二套 40%—70%，商铺 50%—60% |
| 毛租金回报（房价口径） | **6.70%** | 一线 1.5%—2.2%，二三线 2.0%—3.5% |
| 净回报（首付口径） | **22.3%** | 杠杆出租**现金流为负**（见下） |

**关键事实：中国住宅的租金回报率（2%）低于房贷利率（4.9%）。** 这意味着
**杠杆出租的真实净现金流是负的** —— 租金盖不住月供。这就是「买房收租实现财务自由」
在当前市场下不成立的根本原因。

> 那 22.3% 是怎么来的？它对应的是「首付 13.3% + 房价每年涨 8%」——
> **这是 2010—2020 年中国房地产市场的高杠杆行情**：租金回报 6.7%（当时部分城市确实如此）
> 加上房价快速上涨，权益回报率确实能到 20% 以上。
> 但 2021 年之后房价横盘甚至下行，同一套算法会变成 −5% 到 +2%。
> **本作原来的数字没有错，它只是停留在上一个时代。**

### 2.2 各类资产的现实区间与取值

| 类别 | 目标年化（投入口径） | 现实依据 | 本作取值 |
|---|---|---|---|
| 住宅 | 4%—7% | 房价口径净租金 2%—2.5% ÷ 30% 首付，扣维护与空置 | **5.2%** |
| 商业物业 | 6%—9% | 商铺 / 写字楼租金回报 3.5%—5%，显著高于住宅（这也是商铺按「租金回报率」而非「房价收入比」定价的原因） | **7.3%** |
| 车位 | 5%—8% | 车位租金回报高于住宅、低于商铺；但一般难做按揭，首付偏高 | **6.4%** |
| 自营实业 | 9%—13% | 小型生意自己经营净利率可达 20%—30%（含自己的劳动），**雇人打理后**落到 8%—13% | **11%** |
| 品牌加盟 | 7%—11% | 省心但让渡一部分利润 | **9%** |
| 股权投资 | 8%—12% | 参股不控股 | **10%** |
| 固收 | 4%—7% | 银行理财 / 债券基金 3%—5%，高收益债 5%—7% | **5.8%** |
| 自由圈企业 | 10%—15% | 成熟企业的并购回报（P/E 7—10） | **13%** |

> **实业为什么要按「雇人打理」计？** 游戏里买完之后玩家不用投入时间经营（只有精力维护），
> 所以它的回报里**不能包含老板自己的工资**。原来的 ¥43,000 小酒馆月净收入 ¥1,000（27.9%）
> 其实是一个人全职看店的收入 —— 算成「被动收入」是错的。

### 2.3 为什么门槛要加安全边际

真实财务自由的通行标准不是「被动收入刚好等于支出」：

- **4% 法则**本身隐含「资产 = 25 倍年支出」，已经是一重安全边际；
- 真实财务规划里**没有人**会在「被动收入 = 支出」的那一刻辞职 ——
  支出会波动（医疗、通胀、家庭变故、子女教育），零缓冲意味着任何一次意外都会击穿；
- 而「刚好覆盖」还会奖励一种错误策略：**把生活压到最低**，与本作的财商教育目标相反。

所以门槛取 `总支出 × 1.5`（101）/ `× 2.5`（202）。
倍数叠加在原倍数上（101 从 1.0 → 1.5；202 从 2.0 → 2.5，均为 +0.5）。

> 202 之所以不跟着 ×1.5 变成 3.0：实测 ×3.0 会让出圈率掉到 4/12 且几乎只能压线到 60 岁，
> 与「难度提高但可达成」的目标不符。见 §3.2。

三点值得注意：

1. **出圈不再是默认结局**：6 个职业一生未能出圈。这不是失败设计 ——
   单人模式本来就有 S/A/B/C/D/F 六档评级，「未能出圈」对应 C/D，
   而**这才是大多数人的真实结局**。
2. **出圈时点从「30 出头」推到「45 岁前后」**，与游戏自己的人生阶段叙事吻合：
   巅峰期 36—45 岁是「最后一次能让资产追上年龄的机会」。
3. **出圈年龄集中在 43—45 岁**（因为门槛在 45 岁达到峰值）——
   这是一道「中年窗口」：**要么在收入见顶前完成，要么就来不及了。**

### 3.2 202 规则的代价

202 的出圈年龄中位从 42 岁推到 **63 岁**，顺流层只剩 2—6 轮，企业达标线基本无法在局内达成。
这是「更难」的直接代价，也是 202 作为进阶规则的应有之义；
但它意味着**202 的财务自由圈体验被显著压缩** —— 这一点在 §6 列为待评估项。

### 3.4 企业达标线同步下调

财务自由圈的胜利条件之一是「企业月现金流之和 ≥ ¥50,000」。收益口径从 33.5% 降到 13% 后，
**把全部 7 家企业都买下也只有 ¥54,735/月** —— 原达标线等于把这条胜利条件变成不可能。

按比例折算 `50,000 × (13 / 33.5) ≈ 19,400`，取整为 **¥20,000**：
需要约占企业总存量 35% 的资产，与改造前的相对难度一致。

> 顺手做了一件必要的事：这个数字原先在 **20 处硬编码**
> （3 处胜利判定 + 2 处里程碑文案 + 15 处界面文案）。
> 改收益口径时必然漏改，已收敛到 `YIELD.empireTarget` + `Engine.empireTarget()` 单一真源。

## 四、实现方式

### 4.1 单一真源：`window.YIELD`

```js
window.YIELD = {
  mortgageRate: 0.0041,                       // 与 LOAN_TYPES.home.rate 一致（有断言守）
  tier: {
    res:    { down:0.30, rent:0.050 },        // 住宅
    com:    { down:0.45, rent:0.060 },        // 商业物业
    park:   { down:0.40, rent:0.055 },        // 车位
    self:   { net:0.110 }, brand:{ net:0.090 },
    equity: { net:0.100 }, credit:{ net:0.058 }
  },
  ftBusiness: 0.13,
  safetyMargin: 1.5, safetyMargin202: 2.5,
  empireTarget: 20000,
  ...
};
```

每张卡挂一个 `tier` 字段，四个金额字段**全部从 `cost` 反算**：

```
房产：dp = cost × down
      rent = cost × rent / 12
      cf   = rent − (cost − dp) × mortgageRate      ← 房贷「只还息」，与卖出结算自洽
非房产：cf / interest = cost × net / 12
```

**为什么四个字段不能手改**：它们互相约束（首付 → 贷款 → 月供 → 净现金流），
手改任何一个都会让玩家算出对不上的账 —— 而这类错误**不会报错**，
只会让人以为系统算错了（价格标定那一轮已经踩过一次）。

### 4.2 房贷模型：为什么是「只还息」

卡片把房贷简化为**持有期只付息、卖出时一次性还本**：

```
月供 = (房价 − 首付) × mortgageRate
净现金流 = 毛租金 − 月供
卖出时收回 = 首付 + (卖出价 − 总价)      ← 等价于「卖价先偿还贷款，余额归玩家」
```

这与游戏的结算方式**完全自洽**（买入不产生负债、卖出时按总价差额结算）。
之所以不做等额本息，是因为游戏的房产不建模为负债 —— 引入摊还会与「卖出一次性还本」重复计息。

### 4.3 工具与文档的边界

| 文件 | 职责 |
|---|---|
| `window.YIELD`（`data-careers.js`） | 标定基准（唯一真源） |
| `tools/rebalance-returns.js` | 按基准重算 27 张卡的四个字段 + 备注。**幂等**（从 cost 反算，不是乘系数），带「换算后归零即中止」保护 |
| `js/engine.js` | `escapeMargin` / `empireTarget` / `escapeTarget` |
| `test/escape-difficulty.js` | 逐项对账 + 出圈难度实测 |

**备注由字段重新生成**：备注里原本硬编码了金额（`总价 ¥645,000，首付 ¥86,000，出租月收入 ¥3,600`），
只改字段不改备注就会出现「卡面写 ¥2,688、备注写 ¥3,600」。叙事性尾句（如「可联合购买。」）原样保留。

1. **单人模式的过期描述**（3 处）—— 上一轮取消了「机会转让给机构」，但
   `GAME_MODES.solo.desc`、规则页、抽屉交易入口的提示仍在引导玩家去用这个已不存在的功能。
   其中一处是**明确的错误引导**：点「玩家间交易」会弹出「抽到的投资卡可在卡片弹层里『转让给机构』」。
2. **企业达标线 20 处硬编码** —— 见 §3.4。
3. **开局页「规则版本」下的说明漏改** —— 它仍写着「跳出条件：被动收入 > 总支出」，
   与同一屏的规则模块（×1.5）矛盾。**是截图时肉眼发现的**，正则扫描没抓到（它用的是普通 `>` 而非 `&gt;`）。

## 六、刻意保留的偏离与仍未解决的问题

### 6.1 诚实标注：住宅毛租金取 5.0%，高于现实

现实区间是 1.5%—3.5%，本作取 **5.0%**（二三线上沿）。原因：

> 若按严格现实（2.2% 毛租金 + 30% 首付 + 4.9% 房贷），杠杆出租的净现金流为 **负**，
> 房产会退化成纯亏损资产，「投资机会」这条核心玩法随之失效。

所以取的是**低空置率、租赁需求旺盛、利率处于低位的好年份**。
这一偏离写在 `window.YIELD` 的注释里，不藏在代码里。

### 6.2 仍未解决

1. **房产高收益报价的平衡性仍待复核**。当前份额、首付、项目融资与资本利得结算已经统一（见 [资产报价与交易结算](./资产报价与交易结算.md)）；行情卡收购价的分布仍沿用原标定，
   而买入价（首付）被提高了 2.25 倍 → **买入价 vs 卖出价的相对关系变了**。
   实测：`bg1` 首付 ¥193,500，行情卡收购价 ¥860,000，卖出可收回
   `首付 + (860,000 − 645,000) = ¥408,500`（+111%）。
   杠杆买房的资本利得本来就被放大，但**行情卡的报价应当与新的首付比例一起复核** —— 交易计算已统一，价格分布调参尚未做。
2. **持续生活预算已补齐**。住房、用车、消费分别设置预算下限，已有月供和日常消费先抵扣，实际还贷仍能合理降低支出。旧版货运司机门槛下降案例不再代表现行结果。见 [持续生活预算与还贷](./持续生活预算与还贷.md)。
3. **202 的顺流层被压缩**（见 §3.2）—— 出圈中位 63 岁，财务自由圈只剩 2—6 轮。
4. **实业与固收的档位内没有差异**。同一档位（如 `self`）下所有卡片回报率完全相同（11.0%），
   玩家只能在「买得起哪张」之间选择，而不是「哪张更划算」。
   （住宅 / 商业已通过不同档位区分，实业内部还没有。）
