# 家庭收支随人生变化

第二批修复覆盖子女养育、养老金缴费年数与退休基础医疗。它们都进入现有年度账本：每经过一个发薪日或分红日，先结清长岁前的一年，再推进年龄与下一年的收入支出；换回合、刷新或重复打开面板不会增加年数、补发收入或重复扣款。

所有比例都是游戏平衡参数，不是现实教育收费、社保待遇或医疗费用计算器。配置集中在 `FAMILY`，养老金上限继续使用 `SOLO.pensionRatio`。

## 子女分别计龄

新添丁记录父母当时的年龄作为出生时间；孩子年龄 = 父母当前年龄 − 出生时父母年龄，因此多人各自推进，不能由全局轮数计算。

| 子女年龄 | 月养育支出 | 说明 |
|---|---|---|
| 0—17 岁 | 职业卡 `perChild` × 100% | 保留原有养育成本 |
| 18—21 岁 | `perChild` × 50%，取整到元 | 成年过渡支持 |
| 22 岁起 | 0 | 停止定期养育支出，仍保留子女记录 |

每个孩子单独计算，再求和。成年不删除孩子、不恢复添丁名额，仍沿用一局最多三个孩子。

例如每孩基准 240 元，三个孩子分别 22、18、14 岁，则每月支出为 `0 + 120 + 240 = 360` 元。孩子 17→18 岁这一年仍按 240 元结清，下一个结算年改按 120 元；21→22 岁同理。阶段变化会记入日志与里程碑。

## 养老金随记录的缴费年数变化

只有实际结算了一个**在职、有工资、未退休、尚未出圈**的年份，才新增一个缴费年。失业、退休和出圈后不新增；康复或暂停行动本身不增加或减少年数，仍看实际结算年是否领取工资。

```text
养老金比例 = 45% × min(1, 已记录缴费年数 / 41)
月养老金 = 基础工资 × 养老金比例，取整到元
```

连续从 20 岁工作到 61 岁，41 次年度结算后达到原来的 45% 上限；缴费 30 年约为基础工资的 32.93%，零缴费记录为零养老金。61 岁的退休切换仍只用于单人模式；多人年龄模式保留原工资规则，65 岁结束行动。

60→61 岁先结清工资年度，记入最后一个符合条件的缴费年，再确定退休养老金；不会额外补发。养老金保留原有免工资个税处理，也不再受到低精力的工资绩效折扣。

游戏本批**只记录缴费年数，不新增工资扣款项目**，不模拟现实缴费基数、个人账户收益、最低缴费门槛或自愿续缴。出圈后仍按既有规则只领取分红，养老金不会再叠加到分红收入。

## 退休基础医疗与临时医疗分开

仅单人模式已退休时产生基础医疗预算：

```text
月基础医疗 = 基础工资 × min(6%, 2% + (当前年龄 − 61) × 0.5%)，取整到元
月医疗合计 = 退休基础医疗 + 健康危机临时医疗
```

基础工资 4,900 元时，61 岁为 98 元/月，62 岁为 123 元/月，65 岁为 196 元/月。退休前基础医疗为零；这是新增的年龄预算，原有健康危机和事件费用继续保留。

健康危机恢复只移除 `medicalExp`，不会清掉退休基础医疗。财务自由圈仍把养育和医疗纳入生活支出，再应用既有生活档次系数，不会因为出圈而消失。

## 旧存档兼容

按用户确认的方式：**旧存档保留原有养育支出，从更新后开始记录子女年龄**。具体做法是把恢复点作为计龄起点，标注“历史年龄未知 / 更新后计龄”，不按父母年龄猜测出生年份；此后按记录满 18 年、22 年分别切换支出档位。界面会保留这个标记，不把推定年数称为真实年龄。

旧档同样没有逐年缴费记录。为避免在恢复时把已有退休者的养老金突然清零，以 `min(当前年龄, 61) − 20`（最低零）作为已有缴费的兼容估计，标注“含旧档兼容估计 X 年”。从更新后开始，新增年份严格按实际就业和结算记录累计。这是历史兼容假设，不能还原旧局中的失业空档。

迁移不改变现金，不追溯历史结余，也不重算已经锁定的待处理年度缺口；新的账本用于后续结算。重复恢复不会重新推定出生时间、增加缴费年数或重复写入变化通知。

## 数据与展示

`p.family` 随存档持久化：

- `children[]`：`id`、`birthAge`（出生或迁移时父母年龄）、`ageUnknown`。
- `contributionYears`：累计记录的缴费年数。
- `estimatedContributionYears`：其中源自旧档兼容估计的年数，后续不会增加。
- `lastYearAge`：上一次处理过的结算年龄，防止重复累计。

`p.children` 保留总人数兼容原有上限与显示。`familySummary` 统一输出每孩支出、养老金与医疗；`finance`、退休提示、家庭明细和实际年度结算共用这些数值。家庭明细展示月度基础金额，收入支出主表仍以年度口径呈现。

## 验证与边界

`test/family-lifecycle.js` 覆盖 18 / 22 岁边界、多个孩子、跨多个发薪日、失业与出圈缴费、足额与不足额养老金、退休切换、医疗与康复、多人独立年龄及旧档恢复。浏览器 `P` 组覆盖真实财务面板、结算、恢复和兼容提示。

本批不引入配偶收入、婚姻和抚养权变更，也不调整资产管理精力、车贷结清后的持续用车成本或信用卡对应消费基线；这些仍是后续模型范围。
