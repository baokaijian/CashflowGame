# 结算步长与发薪日密度

> **本文是决策记录**：结算步长与发薪日密度必须**搭配**改动，本文记录两组搭配的对照实验
> 与最终决策（2026-09-22 定稿：**方案 A + 内圈 3 个等距发薪日**）。
> 可复跑：`node test/payday-settlement.js`（51 项）、`node test/payday-trigger.js`（87 项）。

## 一、最终口径（定稿）

| 项 | 规则 |
|---|---|
| **结算步长** | 方案 A：一次结算 = 结清「自上次结算以来经过的年数」（`due = ageOf(g) − p.settledAge`，通常 1—3 年） |
| **入账** | `年结余 × due`（年结余 = 当月结余 × 12；这 due 年统一按当前月结余折算，不逐年回溯） |
| **摊还** | due × 12 期（领几年就还几年） |
| **发薪日密度** | 内圈 **3 / 24 格，等距 2 / 10 / 18**（每轮平均经过 ≈0.44 个）· 外圈 **4 / 24 格**（≈1.17 个） |
| **多格** | 同一次移动跨多个结算格 → 只有第 1 个真正结算，其余因本年已结而略过（如实记账，不静默） |
| **零格** | 不结算、不推进、日志不出现发薪记录 |
| **总年数** | 一生累计结算 ≈ 局长度（45 年）—— 密度不改变总年数，只决定「多久结一次账」 |

**等距的结构性副产品**：相邻发薪日间隔 8 格 > 单粒骰子上限 6 步 →
常态下一个回合**最多跨 1 个**发薪日；「一回合跨多个」只在银翅膀（2 粒骰，≤12 步）时发生，
且最多跨 2 个。

## 二、为什么密度与步长必须一起想

「一个发薪日 = 一年」这句话本身**不保证**「一轮 = 一年」。两种错配都实测过：

| 搭配 | 后果 | 结局 |
|---|---|---|
| 每格 1 年 + 3 个发薪日（0.44 个/轮） | 一生只结到约 20 年（覆盖率 44.4%），终局一次性补 25 年 | 从未上线（第一步就否掉） |
| 每格 1 年 + 7 个发薪日（1.02 个/轮） | 覆盖率 101.5% ✓，但**出圈率 50% → 71%**（见 §三） | 上线一天后回滚 |
| **方案 A + 3 个等距发薪日（定稿）** | 覆盖率 ≈100% ✓，出圈率 57%（基线带宽内） | **当前版本** |

方案 A 下密度只决定「分几笔拿到钱」：一生结算总年数恒 ≈ 局长度，与发薪日个数无关 ——
这也是它被选为定稿的原因：**调密度不再牵动难度**。

## 三、实验记录：「每格 1 年 + 7 个发薪日」（2026-09-21，已回滚）

### 3.1 当时的规则

- 每个结算格（内圈发薪日 / 外圈分红日）**恰好 1 年**，跨 N 个结 N 年、无判重。
- 内圈发薪日 3 → **7 / 24 格**（位置 2/5/9/12/16/19/22）：意外支出 3→2、市场行情 4→3、
  添丁 2→1、公益捐赠 2→1 各让 1 格；投资机会保持 8 个不动（其频率决定出圈难度，已单独标定）。
- 外圈分红日 8 → **4 / 24 格**，让出的 4 格给企业投资（6→10）。
  ⚠️ 梦想格必须保持 6 个且 `dream:0—5` 顺序（外圈 4 分红日 + 10 企业的布局**沿用至今**）。

### 3.2 观感收益（真实存在）

| | 方案 A | 每格 1 年 + 7 发薪日 |
|---|---|---|
| 一次落格的入账 | 年结余 × N（N 常为 2—3） | 年结余 × 1 |
| 玩家读到的 | 「结算 3 年」→ 被误读成「结算了 3 次」 | 「经过 3 个发薪日：每个结算 1 年，共 3 年」 |
| 终局补齐的量 | 最多 20+ 年（0.44 密度时）/ 0—3 年（1.02 密度时） | 0—3 年 |

「一次结算覆盖 N 年」的文案歧义靠**算式自证**解决（日志给出「年结余 × N」、
弹层写明「一次结算，覆盖 X—Y 岁共 N 年」），不需要靠改步长解决。

### 3.3 出圈率漂移（回滚的直接原因）

同一 AI、6 种子、12 职业、72 局：

| 指标 | 方案 A + 旧棋盘（3 发薪日） | 每格 1 年 + 7 发薪日 |
|---|---|---|
| 出圈率 | **50%（36/72）** | **71%（51/72）** |
| 出圈年龄中位 | 56 岁 | 55 岁 |
| 一生落格结算次数 | 28.9 次 | 45.7 次 |
| 结算覆盖率 | 84.6%（差额由终局补齐） | 101.5% |

**上升 21 个百分点的原因不是「难度被调低」，而是收入到达的时点变了**：
方案 A 把收入攒成一笔一笔的（隔 2—3 轮才落一次发薪日），
「每格 1 年」让收入从第 1 轮起就均匀到达。测试 AI 要求「买完还剩 2 万现金」，
收入均匀时更容易踩到这条线；一生总收入两者几乎相同，中位年龄也没变。

### 3.4 回滚决策

用户判定 71% 的出圈率「过于简单」，要求把发薪日减回 3 个。
两种修法对比后选择**回滚到方案 A**而不是「保留每格 1 年 + 调高门槛」：

1. 只减发薪日不改步长 → 覆盖率掉回 44%，出圈从「太容易」翻成「几乎不可能」。
2. 每格 1 年 + `safetyMargin` 1.5→1.9 → 实测 57%，但门槛是独立标定过的难度旋钮
   （上一轮刚定为 1.5），不宜为结算口径的连带影响买单。
3. **方案 A + 3 等距发薪日** → 实测 57%（带宽 25%—80% 内）、中位 57 岁，
   且密度与难度解耦 —— 以后再调棋盘不会牵动出圈率。

## 四、定稿后的实测（方案 A + 等距 3 发薪日）

| 指标 | 实测 |
|---|---|
| 出圈率（同 AI · 6 种子 · 72 局） | **57%（41/72）**，基线带宽 25%—80% |
| 出圈年龄中位 | 57 岁（基线 56 岁，等距重排的轻微漂移） |
| 早期（<40 岁）出圈占比 | 5/41 ≈ 12%（个别高收入职业撞热种子，属骰运离群） |
| 发薪日密度 | 0.43 个/轮（标定 0.44） |
| 一生结算总年数 | 39—40 年落格结算 + 突变点/终局补齐 = 全覆盖 45 年 |

## 五、边界情形（都有断言）

1. **跨 0 个结算格** → `settled === null`，现金与 settledAge 都不动，不产生提示。
2. **due = 0（本年已结）** → 记一笔「略过」并明说（提示 kind = `already`），
   不静默；常见来源是失业/退休突变点已把账结到当前年龄。
3. **多年摊还途中负债被还清** → 它的期数停在结清那一刻，期数 < due × 12 属正常。
4. **「最后一次结算之后到退休」的尾巴** → 由终局结清（`finalSettle`）补齐；
   破产路径刻意不做终局结清（破产是现金流断裂的即时判定）。
