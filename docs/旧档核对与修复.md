# 旧档核对与修复

核对日期：2026-09-28。入口为 **设置 → 进度保存与备份 → 历史核对与修正**。修复的目标是消除无处理入口、重复迁移与静默错账，不把缺失的历史猜成事实。

## 自动处理与需核对的内容

| 情况 | 当前处理 |
|---|---|
| 唯一协议成交凭据与当前持仓编号、买方及股数匹配，但成本不符 | 按凭据恢复取得成本，现金和经营年数不变；保留自动核对记录 |
| 旧档无随机状态 | 根据备份内容生成固定的后续序列；同一旧档反复导入不会换骰子或洗牌结果，不声称还原过去种子 |
| 子女出生记录未知 | 保留原兼容规则；有依据时填写当前子女年龄，清除该孩子未知标记，其余孩子不变 |
| 缴费年数含估计 | 可以填写核实后的累计年数，清除兼容估计；未来养老金立即更新，不重发过去的钱 |
| 初始房产融资混入其他债务 | 输入确认的重复本金、对应持仓和剩余其他债务合同月供；可以转入仍持有的房产、按还本凭据移除已售重复债务，或确认独立债务保留 |
| 同名多个房产、产权分散 | 按持仓编号选择实际承接者；共有租金按整套与份额核验，可分步拆分，最后一次才关闭待核对状态 |
| 非房产取得成本或理财本金缺证据 | 有原始依据后按具体持仓填写取得总款；股票保留非整数单位成本，不以新卡报价替换旧本金 |
| 已发生错误兑付等现金错账 | 核对全部差异后填写确认的当前余额；不会把一个差额反复补入，也不会自动重放兑付 |
| 已售房产记录彻底丢失 | 有售房凭据时补录名称、价格、租金、份额、首付比例、持有年数与纯资本属性，已有原实体时继续使用原编号，校验尚未登记的份额，下一次行动起挂牌；不补发售房款 |
| 日志、财富历史截断 | 可选择同一局的历史完整备份，补入仍可找到的原记录，独立归档，不覆盖当前曲线或倒推过去现金 |

子女、融资、金额或持仓不合法时拒绝。自动成本恢复要求唯一结构化凭据，不能只凭同名或自然语言日志。已人工核对的成本不会再次被旧成交记录覆盖。

## 一次修正的流程

1. 选择玩家、核对项目和具体持仓，填写原始依据。姓名、职业相同并不能证明两份备份来自同一局，补历史时还需人工确认来源。
2. 点击“预览修正”：展示字段前后差异、现金及月净额变化。预览和取消不改变账本。
3. 确认后重新校验当前对局。如果预览后又发生交易、恢复或其他状态变化，旧方案失效，需要重新预览。
4. 在独立本地槽保存修正前完整原档，再写入校验后的新档。写入失败不切换当前局；界面安装失败沿用存档回滚机制。
5. 修正依据、前后值和轮次保留在完整存档内，可通过“下载核对与补充历史”查阅。历史核对报告不是可续局的存档。

自动恢复成交成本时，浏览器恢复/导入流程同样保留原始存档。最近一次修正前原档可从设置下载，再用正常完整备份导入流程回退。原档槽只保留最近一次；需要多步回退时，应每次下载保管。存储空间不足时不要刷新，先导出当前完整备份。

## 防止修正再次造成错账

- 不调用发薪、还款或兑付动作；已锁定年度缺口和待处理账单不重算。修正期间已经生成但尚未执行的骰子必须先完成。
- 贷款只移除确认的重复部分，不把全部“其他负债”一并清零。剩余合同月供须明确填写，不能凭比例猜。
- 同一房产的共有毛租金必须一致，其他持有人的租金变化也列入预览；产权总和超过一套时拒绝。
- 现金使用最终目标余额；同一结果再提交没有差异。已完成的融资修正再次提交会被拒绝；分步修正须明确保留待核对状态。
- 已售挂牌补录要求唯一凭据编号，防止重复补录；只适用于确认未重新登记的历史房产，已有同名实体需先选择原实体；只有凭据证明为另一套时才可另建，不能用来复制当前资产。
- 补入历史按原记录去重，重复导入不产生新记录。历史档案保存到 `g.recovery.archive`，不受普通自动日志 80 条裁剪影响；原始财富曲线仍保留原始采样。
- 不追溯修改成就统计、过去财富峰值或历史收入，不将人为核对冒充游戏投资收益。

## 数据、容量与边界

`g.recovery` 记录版本、递增编号、核对条目及补充档案；每份完整存档最多 1,000 条核对、3,000 条补充日志、1,000 条补充财富记录，仍受完整文件 2,000,000 字符等总体限制。超过上限明确拒绝，不静默截断补充证据。修正前原档使用独立本地键 `cf_repair_before_v1`，普通对局键不变。

完全没有备份、凭据或可靠记忆的信息依然无法恢复。玩家可以继续使用明确标注的兼容值；不能把确认按钮当成消除事实不确定性的办法。补录已删除的房产需要足够描述其后续交易的字段，也不能恢复未知的过去租金。没有旧随机种子时只能保证更新后的连续性。

本地核对属于单机维护工具，不提供服务器防作弊或第三方凭据真实性认证。多人共用设备时，修改前应由参与者核对依据。
