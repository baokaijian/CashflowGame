# 旧档兼容与内部核对

核对日期：2026-09-28。游戏只提供自动保存与启动时自动续局。之前的手动备份、导入、恢复和历史核对入口已移除；本页区分仍生效的自动迁移与内部维护能力。

## 自动迁移

- 唯一协议成交凭据与当前持仓身份、买方和股数匹配时，恢复取得成本；不重付现金或重置经营年数。已人工核对的成本不被旧记录覆盖。
- 缺少随机状态的旧档按其内容确定后续序列；同一旧档不会因不同恢复时间而换序列，不声称恢复过去种子。
- 可可靠识别的初始房产融资移入对应资产；混合债务、来源或产权不明则保留原账与提示，不能直接减掉整笔其他债务。
- 未知子女年龄继续从兼容起点计龄；未知缴费年数保留估计标记。不重算过去现金或锁定事件。
- 已有核对记录及补充历史继续保存在 `g.recovery`，移除入口不清除原有数据。

## 内部维护能力

`SaveState.planRepair` 与相关安装函数保留供代码维护及回归使用，**不是可从游戏界面打开的功能**。它们可以在副本上核对家庭、融资、非房产成本、现金、已售房产和历史档案。要求依据、身份和金额校验，输出前后差异；应用时校验源状态、先保留原档，失败不替换当前账本。

同名房产不自动合并，现存实体优先保留原编号，已有份额不能重复补录。补充历史与当前账本、曲线分开；不存在通过截断日志倒推补发现金的自动逻辑。独立原档键为 `cf_repair_before_v1`，游戏不提供下载和回退控件。

核对数据最多 1,000 条，补充日志最多 3,000 条，补充财富记录最多 1,000 条，仍受整体存档大小限制。这些数据仅随本地状态保留，没有云同步或界面导出。

## 事实边界

彻底缺失且没有可靠凭据的出生、缴费、成交、租金、随机与财富历史无法真实重建。自动兼容保证后续规则可运行，不代表未知历史已得到确认。移除手动入口后，玩家不能在游戏中输入假定金额来消除兼容提示。

[legacy-repair.js](../test/legacy-repair.js) 继续验证内部核对、幂等和失败保护；浏览器 AC 组验证没有手动入口、正常自动续局、无缓存的新游戏及自动成本迁移。详见 [存档说明](存档保护与随机状态.md)。
